## 하는 중 — 3단계 4 (나) 외교 · 영토 (게임의 함수를 부른다 — 기능마다 사용자의 승인)

- **식민지화**: 승인받아 구현했다(브랜치 `feat/toybox-colonize-call`). 게임 안 확인 C0 ~ C3 도 끝났다(설계서의 표). 식민지 · 동맹은 게임의 외교 부서 패널에서 지도의 그 나라를 눌러 본다.
- **전쟁 붙이기**: 승인받아 구현했다(브랜치 `feat/toybox-fight`). 플레이어가 끼는 경우는 막지 않는다(사용자가 정했다). 게임 안 확인 F0 ~ F3 도 끝났다(설계서의 표). 판을 막 시작하면 "지도에서 고른 나라"가 플레이어의 나라다 — 그대로 누르면 플레이어가 선포한다. 두 나라 사이의 전쟁은 외교 패널 아래 줄의 둘째(빨간) 아이콘의 툴팁 `N 적 지역`에서 본다. `gamedrive.py wheel` 은 ToyBox 창 위에서 탭을 굴리지 못하고 지도를 축소한다 — 스크롤 막대의 길을 눌러 굴린다.
- **이 나라로 플레이**: 승인받아 구현했다(브랜치 `feat/toybox-become`, 2026-10-11). 전역 넷을 쓴다 — 지역 객체 밖에 쓰는 것은 이 기능뿐이다. 게임 안 확인 B0 ~ B3 에서 첫 자정 뒤로는 거부되는 것을 찾아 고쳤다(브랜치 `fix/toybox-become-after-midnight` — 둘째 포인터는 첫 자정부터 "전날 사본"을 가리킨다). 고친 빌드로 첫 자정 뒤의 전환 · 되돌아오기도 게임에서 봤다(B4).
- **지도자 제거**: 승인받아("셋 다") 구현했다(브랜치 `feat/toybox-novichok`). 게임이 지도자가 죽은 날 스스로 하는 일과 같다. 게임 안 확인 N0 ~ N3 도 끝났다(설계서의 표).
- **동맹 맺기**: 승인받아 구현했다(브랜치 `feat/toybox-treaty`). 대상은 목록에서 고른 나라, 이미 동맹이면 아무것도 안 한다(사용자가 정했다). 게임 안 확인 T0 ~ T3 도 끝났다(설계서의 표).
- **병합**: 승인받아 구현했다(브랜치 `feat/toybox-annex`). 게임 안 확인 X0 ~ X3 도 했다(덴마크 345칸, 1초 안). **2030 - 세계에서 지역 인덱스: 독일 176 · 폴란드 141 · 덴마크 157**(150 은 가짜 판의 값이다 — 게임에서는 다른 나라다. 인덱스는 지역 표에서 번호로 찾아 확인할 것). 병합 뒤 화면 밖 게임에서 지도의 이동 · 확대가 듣지 않던 것은 병합 · ToyBox 탓이 아니었다(X4 — ToyBox 를 열지 않은 프로세스에서도 생겼고 다시 띄우면 사라진다). **게임 안 확인의 주의**: 메인 메뉴가 그려진 뒤 8초를 기다리고, 샌드박스를 누른 뒤 로비인지 스크린샷으로 확인하고 나서 다음 명령을 보낸다 — 2026-10-11 에 누름이 `불러오기` 화면으로 들어가 로비용 명령이 사용자의 저장 목록 화면에서 실행된 일이 있었다(저장 파일 · 설정은 바뀌지 않았다). 지도 조작이 듣지 않으면 게임을 다시 띄운다.
  이것으로 묶음 4(인구 · 외교 · 영토)의 코드가 끝난다. 다음은 묶음 5(부대: 생성 · 보급 · 최강 부대 묶음 + 부대 목록 · 보급 · 경험의 세분화).
- (지난 메모) 병합은 지도의 칸마다 함수를 부른다 — 가장 무겁다. 외교·영토 탭에 내장 치트로 남은 줄은 병합뿐이다(화면 검사의 `confirm_fault` 가 그 줄을 쓴다 — 병합을 옮길 때 다른 탭의 치트 줄로 바꾼다).
- 나머지(병합)는 설계서의 표에 치트가 부르는 함수가 있다. 하나씩 인자를 확인해 제안하고 승인받는다.
  새 함수는 `locate.cpp` 의 표 ACTS 에 한 줄(서명 셋 — `srkit sig-mine <RVA> --back 2`), `game` 에 가드 안의 호출, `keeper` 의 줄을 쓴다.
- **분석할 때 주의**: 게임 폴더에 `MapEditor.exe` 가 함께 있다 — 실행 파일은 반드시 `srkit.toybox.EXE_NAME`(`SupremeRuler2030.exe`)으로 연다.
  (2026-10-10 에 스크래치 스크립트가 크기만 보고 골라 MapEditor 를 읽었다. 구조체의 자리는 같았지만 함수의 주소가 달랐다.)
  스크립트 이름을 `dis.py` 로 짓지 말 것(표준 모듈을 가린다).

## 부대 (3단계 5) — 2026-10-11

- 설계도 목록: 끝, 게임에서 봤다(U1 ~ U4, F1 ~ F4). F 에서 남은 셋(풍선말의 길이 · 보유국 칸의 너비 · 아랫줄)은 `feat/toybox-spawn` 에서 고쳤고 게임 안 확인 전.
- **부대 생성**: 승인받아 구현했다(브랜치 `feat/toybox-spawn`). 게임 안 확인 S1 ~ S4 도 했다(설계서의 "게임에서 본 것 — 부대 생성").
  만든 전차가 없어지던 것은 게임의 동작이다 — 치트로 만든 것과 같았다(바다의 육군은 사라지고, 남의 땅의 부대는 스스로 떠난다. 설계서의 T1 ~ T4).
  게임 안 확인에서 부대는 **독일 땅**에 만들 것. 부대의 목록은 국방 단추 → `지휘` 패널. "지도에서 고른 칸"은 `[0x1764338]`(dword, 가로 | 세로 << 16), 함수는 `0x79E2F0`.
- **고른 부대의 보급**: 사용자가 "치트의 셈을 그대로"로 정해 구현했다(브랜치 `feat/toybox-supply`). 게임 안 확인 L1 ~ L4 도 했다(치트로 채운 것과 같은 값). 남의 부대를 고른 경우는 게임에서 보지 못했다.
  게임에서 부대를 고르려면 지도의 부대 칸을 두 번 눌러 뜨는 부대 줄을 누른다. 부대 객체의 자리들은 설계서에 있다. 설계의 선행 기술이 넷이 아니라 둘일 수 있다는 물음이 남았다(설계서).
- **최강 부대 묶음**: 승인받아 구현했다(브랜치 `feat/toybox-best-units`) — "받기" 쪽만, 게임이 정한 배치 칸에, 영역 · 수량을 고른다.
  `0x7EE8E0` 은 받기가 아니라 적 부대를 없애는 쪽의 함수였다(옮기지 않았다). 게임 안 확인 B1 ~ B4 도 했다 — 수와 자리는 치트와 같고, 치트는 병과를 넘어가며 고르는 탓에 8종만 준다(ToyBox 는 17종. 설계서).
- **즉시 승리**: 승인받아 구현했다(브랜치 `feat/toybox-victory`). 게임 안 확인 V1 ~ V3 도 했다(승리 창 · 계속 진행. 꼴이 1 로 남아 한 판에 한 번이다).
- **GUI 숨기기/보이기**: 승인받았고 분석 끝(함수 표 `0xC57190` 의 5번 `0xC03D60`). 화면 검사 34곳이 이 줄을 "남은 치트 단추"로 쓰므로 치트 경로 제거와 한 묶음으로 한다.
- 돌고 있는 게임의 메모리를 읽는 분석용 스크립트는 `gamedrive.py` 의 `owned_pids` · `ReadProcessMemory` 로 짠다(읽기만. 검증 에이전트가 띄운 게임에도 쓸 수 있다).
- 다음: 치트 경로 제거 + GUI 숨기기 → 세분화(경험 등) → 묶음 7(배율).
- 화면 밖 게임에서 ToyBox 의 입력란에는 `type` 이 들어가지 않는다 — `key 0x23`(End) → `key 0x08` 여러 번 → 숫자 글쇠 → `ENTER`.
- 화면 밖 게임에서 ToyBox 창 위의 휠은 듣지 않는다 — 스크롤 막대의 길을 누른다. `gamedrive.py` 에 끌기가 없어 열 너비는 바꿔 보지 못한다.
