## 끝난 것 3 — 3단계 3 (나) 연구의 목록 (브랜치 `feat/toybox-research-list`, PR #51)

코드 · 자동 테스트(`uv run pytest` 571 passed) · 게임 안 확인 R6 ~ R11 · 문서가 끝났다. 본 것과 보지 않은 것은 [docs/10](../../10-toybox.md)의
"확인한 것 — 3단계 3 (나)"와 [설계서](../specs/2026-10-10-toybox-stage3-3-design.md)의 "(나) — 연구의 목록".

**남은 것(작다)**: 한글 부대 이름을 고친 뒤의 화면을 게임에서 다시 보지 않았다. 찾기란에 한글(IME)이 들어가는지 보지 않았다.
쓴 뒤에도 고른 것이 남는 것을 그대로 둘지는 사용자가 정한다.

**게임 안 확인을 다시 할 때**: 로비의 샌드박스 목록이 DLC 로 길어졌다 — 휠로 11칸 내린 뒤 `click 790 259` 가 "2030 - 세계"였다(앞 문서의 `click 797 240` 은 아니다).
`gamedrive.py key` 의 숫자는 `0x30` ~ `0x39` 로 준다. `PYTHONUTF8=1` 을 주면 `gamedrive.py` 가 죽는다(`PYTHONIOENCODING=utf-8` 만).

**고치지 않기로 본 것**: `game_write_research` 가 C++ 예외를 던질 때의 깃발, 다시 셈에서 예외가 났을 때의 로그, 연구 목록과 다른 전역의 겹침,
"게임 밖"을 글로 가르는 것, `gamedrive.py research --out` 의 인자 확인.

## 끝난 것 4 — 3단계 4 (가) 인구 · 지지율 (PR #54, 그 뒤의 손질은 `fix/toybox-people-verified`)

"인구 +100만" · "내 나라 지지율 100%"가 값을 직접 쓴다. 게임에서 본 것은 [설계서](../specs/2026-10-10-toybox-stage3-4-design.md)의 P1 ~ P5.
내장 치트의 인구는 첫 자정에 되돌아갔다 — 원천을 조사해(설계서의 "인구의 원천") **인구 칸 + 인구의 풀 칸(`+0x14B58`)**에 쓰게 고쳤다(브랜치 `feat/toybox-people-lasting`).
단추로 쓴 판에서 인구가 유지되는 것은 사용자가 직접 봤다(2026-10-10). 분석용 스크립트(메모리의 인구 칸들을 읽고 풀에 더한다)는 스크래치에만 있었다 — 저장소에는 없다.

## 하는 중 — 3단계 4 (나) 외교 · 영토 (게임의 함수를 부른다 — 기능마다 사용자의 승인)

- **식민지화**: 승인받아 구현했다(브랜치 `feat/toybox-colonize-call`). 게임 안 확인 C0 ~ C3 도 끝났다(설계서의 표). 식민지 · 동맹은 게임의 외교 부서 패널에서 지도의 그 나라를 눌러 본다.
- **전쟁 붙이기**: 승인받아 구현했다(브랜치 `feat/toybox-fight`). 플레이어가 끼는 경우는 막지 않는다(사용자가 정했다). 남은 것은 게임 안 확인 F0 ~ F3(설계서).
- 나머지 넷(이 나라로 플레이 → 지도자 제거 → 동맹 → 병합)은 설계서의 표에 치트가 부르는 함수가 있다. 하나씩 인자를 확인해 제안하고 승인받는다.
  새 함수는 `locate.cpp` 의 표 ACTS 에 한 줄(서명 셋 — `srkit sig-mine <RVA> --back 2`), `game` 에 가드 안의 호출, `keeper` 의 줄을 쓴다.
- **분석할 때 주의**: 게임 폴더에 `MapEditor.exe` 가 함께 있다 — 실행 파일은 반드시 `srkit.toybox.EXE_NAME`(`SupremeRuler2030.exe`)으로 연다.
  (2026-10-10 에 스크래치 스크립트가 크기만 보고 골라 MapEditor 를 읽었다. 구조체의 자리는 같았지만 함수의 주소가 달랐다.)
  스크립트 이름을 `dis.py` 로 짓지 말 것(표준 모듈을 가린다).
