## 목적

3단계는 ToyBox 의 모든 기능을 게임의 내장 치트에서 떼어 내는 일이다(요구 3). 묶음 1 에서 돈 · 물자를 옮겼고, 내장 치트로 도는 기능이 19개 남았다.
**이 묶음은 그 가운데 "값만 고치는" 넷을 옮긴다** — 끝나면 15개가 남는다.

| 탭 | 단추 | 지금 넣는 치트 |
|---|---|---|
| 연구 | 지식 순위 올리기 | `cheat finalexam` |
| 인구·여론 | 세계 시장 여론 최고 | `cheat shelovesme` |
| 외교·영토 | 관계 최고 | `cheat love <지역 번호>` |
| 외교·영토 | 관계 중립 | `cheat neutral <지역 번호>` |

ToyBox 의 요구 셋(게임 안의 설정 창에서 / 플레이어가 플레이하는 국가에만 / 내장 치트와 완전히 별도로)과 "내장 치트와 별도"의 뜻("찾기까지 분리"),
전환 기간의 예외("옮기지 않은 기능은 당분간 지금 방식")는 앞 묶음의 설계서 그대로다.

## 설계 전에 확인한 것

조사는 정적 분석 하나다: 설치된 실행 파일을 읽어 Python(capstone)으로 봤다. 게임은 띄우지 않았고 게임 폴더에는 쓰지 않았다.
분석에 쓴 스크립트는 저장소 밖에 있다. 치트 명령 처리 함수는 RVA `0x522330` – `0x5284fd` 다.

### 치트가 하는 일 [확인: 정적]

넷 모두 **게임의 다른 함수를 부르지 않고 float 칸에 쓰기만 한다.** `love` · `neutral` 의 본문에 있는 `call` 셋은 쓰기보다 앞에서 명령 글의 지역 번호를 읽는 것이다
(공백을 찾고 십진수로 바꾼다 — 인자의 모양으로 본 것이다 [추정]).

| 치트 | 본문 | 하는 일 |
|---|---|---|
| `finalexam` | `0x524226` | `[플레이어 지역 객체 + 0x14CD0]`(float)에 1.0 을 더한다 |
| `shelovesme` | `0x5241db` | `[플레이어 지역 객체 + 0x14B10]` · `[+0x14AF8]` · `[+0x14AF4]`(float)에 1.0 을 쓴다 |
| `love <번호>` | `0x5239de` | 그 번호의 지역 객체 `T`(인덱스 `t`)와 플레이어 객체 `P`(인덱스 `p`)에 대해: `P[+0x16F10 + 4t]` = 1.0, `P[+0x15F10 + 4t]` = 1.0, `P[+0x17F10 + 4t]` = 0, 그리고 `T[+0x16F10 + 4p]` = 1.0, `T[+0x15F10 + 4p]` = 1.0, `T[+0x17F10 + 4p]` = 0 |
| `neutral <번호>` | `0x523b29` | 같은 여섯 칸에 모두 0 |

- 인덱스는 지역 객체의 `+4`(word)이고 플레이어의 것은 전역 "플레이어 지역의 인덱스"다 — 둘 다 묶음 1 에서 ToyBox 가 이미 읽는 값이다.
- 지역 객체 안에 **지역 인덱스로 찾는 float 표가 셋** 있다: `+0x15F10`, `+0x16F10`, `+0x17F10`. 서로 `0x1000` 떨어져 있다 = 4바이트 × 1024칸(지역 표의 칸 수와 같다).
- 값의 범위: `cheat hate` 가 앞의 두 표에 −1.0, 셋째 표에 1.0 을 쓴다. 앞의 둘은 −1.0 ~ +1.0 의 관계 값(0 이 가운데), 셋째는 0 ~ 1.0 이다.
- 치트는 지역 번호를 게임의 번호 → 인덱스 표로 풀거나 지역 표를 훑어 찾는다. ToyBox 는 나라 목록을 만들 때 이미 지역 표를 훑는다 — 그 길로 찾는다.
- `finalexam` 이 더하는 상수는 읽기 전용 자료 `0xc568dc` 의 float 1.0 이다.

### 칸의 뜻

| 자리 | 뜻 | 근거 |
|---|---|---|
| `+0x14CD0` | 기술 수준(1900 년부터의 햇수) | **[추정]** 치트 밖의 코드(`0x55320f`)가 이 값을 정수로 바꿔 1900 을 더한다 [확인: 정적]. 위키는 `finalexam` 을 "기술 수준 +1"이라고 한다. 게임에서는 지식 지수 순위가 6위 → 1위로 오르는 것만 봤다([07](../../07-cheats.md)) |
| `+0x14AF4` · `+0x14AF8` · `+0x14B10` | 세계 시장 여론과 그 둘레의 값 | 어느 칸이 화면의 어느 숫자인지는 **모른다**. 치트로 셋을 1.0 으로 만들면 세계 시장 여론 "매우 기쁨", 보조금률 100%, 조약 신뢰도 92.5% 가 됐다([07](../../07-cheats.md)) |
| `+0x15F10` · `+0x16F10` 의 표 | 다른 지역과의 관계(외교 · 민간). 어느 표가 어느 막대인지는 **모른다** | 치트 `love` 뒤에 두 막대가 가득 찼다([07](../../07-cheats.md), [10](../../10-toybox.md)의 H5) |
| `+0x17F10` 의 표 | 다른 지역에 대한 전쟁 명분 | **[추정]** `love` · `neutral` 이 0 을, `hate` 가 1.0 을 쓰고, 화면에서 `love` · `neutral` 뒤에 전쟁 명분이 0 이었다 |

**뜻을 몰라도 옮길 수 있다** — 이 묶음은 치트가 쓰는 칸에 치트가 쓰는 값을 쓸 뿐이다. 뜻은 게임 안 확인에서 본 만큼만 문서에 적는다.

### 치트 코드 없이 찾을 수 있는가 [확인: 정적]

`uv run srkit sig-mine --offset <자리>` 로 봤다. 일곱 자리 모두, 치트 코드 밖의 서로 다른 함수 여럿에서 서명 후보가 나온다.

| 자리 | 후보가 나온 함수의 수 | 비고 |
|---|---|---|
| `+0x14CD0` | 20 | |
| `+0x14B10` | 8 | 스택의 자리가 우연히 같은 코드가 섞여 있다 — 지역 객체를 읽는 것만 고른다(다섯은 그렇다) |
| `+0x14AF8` | 31 | |
| `+0x14AF4` | 25 | |
| `+0x15F10` | 43 | `movss xmm, [객체 + 인덱스*4 + 자리]` 꼴 |
| `+0x16F10` | 28 | 〃 |
| `+0x17F10` | 22 | 〃 |

서명 표의 실제 바이트는 구현 계획에서 고른다(묶음 1 과 같다: 찾을 것마다 서로 다른 함수의 서명 셋).

### 아직 보지 않은 것

1. ToyBox 가 그 칸들에 직접 쓴 뒤의 게임 화면이 치트를 넣었을 때와 같은지. 치트가 하는 일이 그 쓰기뿐이므로 같을 것으로 본다 [추정] — **이 설계의 전제다.**
2. `+0x14CD0` 이 기술 수준인지, 값이 얼마인지(2030 년 시작이면 130 근처일 것으로 본다 [추정]).
3. 여론의 세 칸과 관계의 두 표가 화면의 어느 숫자 · 막대인지.
4. 쓴 값이 얼마나 오래 가는지(게임이 날마다 관계와 여론을 다시 셈한다면 치트와 마찬가지로 서서히 바뀐다).
5. 한쪽 방향만 쓴 관계를 게임이 어떻게 보이는지 — 이 설계는 양쪽에 쓰므로 보지 않는다.
6. DLC 의 판과 다른 빌드.

## 범위

**넣는 것**

1. 새 찾기 묶음 셋: **지식**(기술 수준 칸) · **여론**(세 칸) · **관계**(표 셋) — 모두 치트와 무관한 서명으로.
2. 읽기와 쓰기: 플레이어 객체의 기술 수준 1칸 · 여론 3칸 · 관계 표 셋에서 고른 나라의 칸, 그리고 고른 나라 객체의 관계 표 셋에서 플레이어의 칸.
3. 값 쓰기 요청 세 가지(기술 수준 +1, 여론 최고, 관계 최고/중립)를 묶음 1 의 대기열에 더한다.
4. 단추 넷을 직접 쓰기로 바꾼다. 이름 · 탭 · 자리는 그대로다. 기능 표에서 내장 치트로 도는 줄은 19 → 15.
5. `uv run srkit locate` 가 새 묶음 셋의 결과를 보인다. `scripts/gamedrive.py peek` 이 새 값들을 읽는다(검증용, 읽기만).
6. 문서와 규칙(쓰는 곳의 목록).

**넣지 않는 것**

- 지금 값의 표시, 관계 최저 · 임의 값, 여론 최저, 기술 수준 내리기 · 값 입력, 관계 · 여론의 최소 유지.
- 플레이어가 끼지 않는 두 나라 사이의 관계. 지도에서 고른 나라를 대상으로 삼는 것(대상은 지금처럼 창의 목록에서 고른 나라다).
- 나머지 15개 기능의 분리(묶음 3 ~ 6), 치트 경로의 삭제(마지막 묶음), 배율(묶음 7).
- 쓴 뒤 열려 있던 게임 패널을 다시 그리게 하는 것(묶음 1 의 한계 그대로 — 패널을 누르거나 다시 열면 따라온다).
- 멀티플레이.

## 구성

```
srtoybox.dll
  locate    ── (더함) 새 찾기의 묶음 셋: 지식 · 여론 · 관계. 묶음마다 따로 찾고 따로 실패한다
  game      ── (더함) 기술 수준 · 여론 · 관계의 읽기와 쓰기. 지역 번호 → 그 지역의 객체와 인덱스
  keeper    ── (더함) 요청의 종류 셋. 대기열 · 타이머 · 오류 뒤의 처리는 그대로
  features  ── (고침) 네 줄이 "명령" 대신 "직접 쓰기의 종류"를 갖는다. 내장 치트로 도는 줄 15
  ui        ── (고침) 직접 쓰는 줄은 대기열에 요청을 넣는다. 쓸 수 없으면 단추 자리에 까닭
srkit locate / gamedrive.py peek ── (더함) 새 묶음의 결과, 새 값의 읽기
```

`sigs` · `values` · `products` · `settings` · `input` 은 바뀌지 않는다(설정 파일에 더할 키가 없다 — 네 단추에는 저장할 값이 없다).

### 새 찾기 (`locate`)

| 묶음 | 찾을 것 | 읽어 낼 것 | 못 찾으면 |
|---|---|---|---|
| 지식 | 기술 수준 칸 | 상수(4바이트) | "지식 순위 올리기"만 꺼진다 |
| 여론 | 여론의 세 칸 | 상수 셋(찾을 것 셋) | "세계 시장 여론 최고"만 꺼진다 |
| 관계 | 관계 표 둘, 전쟁 명분 표 | 상수 셋(찾을 것 셋) | "관계 최고" · "관계 중립"만 꺼진다 |

- 규칙은 묶음 1 과 같다: 찾을 것마다 서로 다른 함수의 서명 셋, 실행 구역에서 정확히 한 번 맞은 것이 둘 이상이고 값이 모두 같아야 "찾았다". 서명은 치트 코드 밖에서만 뽑는다.
  새 서명은 7 × 3 = 21개다(지금 33개).
- **묶음마다 따로 찾는다.** 한 묶음이 깨져도 다른 묶음과 묶음 1 의 값(돈 · 물자), 상태 읽기는 그대로다. 여론과 관계는 묶음 안의 셋을 모두 찾아야 그 묶음을 찾은 것이다
  (셋 가운데 둘만 쓰는 반쪽 쓰기를 하지 않는다).
- 읽어 낸 값의 대조 — 하나라도 아니면 그 묶음은 "못 찾았다":
  - 자리는 0 보다 크고 `0x100000` 보다 작은 4 의 배수다(칸이 float 다).
  - 여론의 세 칸은 서로 다르다.
  - 관계의 표 셋은 서로 `0x1000`(4바이트 × 지역 표의 1024칸) 이상 떨어져 있다.
  - 새 칸들이 서로, 그리고 묶음 1 의 국고 칸(8바이트) · 재고 칸들과 겹치지 않는다(묶음 1 의 값을 찾았을 때). 기술 수준 · 여론의 칸이 관계 표 안에 들지 않는다.
- 지역 객체 머리의 자리(`+0` 상태, `+4` 인덱스, `+8` 번호)와 지역 표의 칸 수 1024 는 지금처럼 상수다.

### 읽기와 쓰기 (`game`)

- **대상 찾기**(관계): 지역 번호로 지역 표를 훑어 객체와 인덱스를 얻는다. 받아들이는 조건 — 객체 포인터가 NULL 이 아니다 / 객체의 `+8` 이 그 번호다 /
  객체의 `+4` 가 표에서의 자리와 같다 / 객체의 상태(`+0`)가 2 또는 3 이다(이번 판에 실제로 있는 나라 — 나라 목록과 같은 기준) / 플레이어 자신이 아니다.
- **읽기**: 기술 수준(float), 여론의 세 칸, 한 나라와의 관계 여섯 칸(내 쪽 셋 · 그 나라 쪽 셋). 묶음 1 의 안전한 읽기로 읽는다. 쓰기 전의 확인과 검증 도구가 쓴다 — 창에는 보이지 않는다.
- **쓰기 직전에 매번 다시 확인한다**(하나라도 아니면 쓰지 않는다): 그 묶음을 찾았다 / 값 쓰기가 켜져 있다 / `in_game` 이다(일관성 포함) / 멀티플레이가 아니다 /
  쓸 자리가 읽기 · 쓰기 쪽이다 / (관계) 위의 대상 조건 / (기술 수준) 읽은 값이 유한한 수이고 0 이상이며 1 을 더한 값이 999 이하다.
- **쓰기**: 묶음 1 과 같다 — 자기 프로세스에 대한 `WriteProcessMemory`, 쓴 뒤 다시 읽어 그 값인지 보고 아니면 한 번 더.
  - 기술 수준: 읽은 값 + 1.0.
  - 여론: 세 칸에 1.0.
  - 관계 최고: 내 쪽 관계 둘 1.0 · 전쟁 명분 0, 그 나라 쪽도 같게. 관계 중립: 여섯 칸 모두 0.
- 여러 칸을 쓰는 요청은 칸마다 쓰고 확인한다. 도중에 하나가 실패하면 거기서 멈추고 실패로 친다(앞서 쓴 칸은 되돌리지 않는다 — 로그에 어디까지 썼는지 적는다).
- **쓰는 곳이 늘어난다.** `game.h` 의 머리말과 CLAUDE.md 의 그 줄을 이렇게 고친다: ToyBox 가 게임의 메모리에 쓰는 곳은
  **플레이어 지역 객체의 국고 1칸 · 재고 12칸 · 기술 수준 1칸 · 세계 시장 여론 3칸 · 관계 표 셋에서 고른 나라의 칸**, 그리고
  **고른 나라의 지역 객체의 관계 표 셋에서 플레이어의 칸**뿐이다. 전역 · 치트 허용 비트 · 그 밖의 지역에는 쓰지 않는다.

### 요청과 대기열 (`keeper`)

- 요청의 종류 셋을 더한다: 기술 수준 +1 / 여론 최고 / 관계(대상의 지역 번호와 수준 — 최고 · 중립).
- 길은 묶음 1 그대로다: 창의 단추(그리는 스레드)가 대기열에 넣고, 게임 창의 타이머(창 스레드)가 비우며 쓴다. 게임 밖 · 멀티플레이 · 오류 가드 뒤에는 남은 요청을 버린다.
  직접 실행이 게임의 함수 안에 있는 동안 다시 온 타이머에서는 쓰지 않는다.
- 쓴 뒤 창 바닥의 `마지막으로 쓴 값` 과 로그에 한 줄을 남긴다(아래 "로그"). 쓰지 못했으면 묶음 1 처럼 알림 한 줄.
- 최소 유지와는 상관없다(유지는 국고와 물자뿐이다).

### 기능 표와 창 (`features` · `ui`)

- 기능 표의 줄은 그대로 19줄이고 순서도 그대로다. 네 줄(`finalexam` · `shelovesme` · `love` · `neutral`)은 "게임에 넣는 글" 대신 **직접 쓰기의 종류**를 갖는다.
  내장 치트로 도는 줄은 15줄이다 — 로그의 `옛 방식(내장 치트)으로 도는 기능이 N개 남아 있습니다` 와 문서의 수가 15 가 된다.
- **단추의 이름 · 탭 · 자리는 바뀌지 않는다.** 설명 글은 본 대로 고친다: "지식 순위 올리기"는 게임 안 확인에서 기술 수준임을 보면 그렇게 적고, 못 보면 지금 글 그대로 둔다.
- 직접 쓰는 줄의 단추가 켜지는 조건: 게임을 읽는다 · 진행 중이다 · 멀티플레이가 아니다 · 오류 가드가 걸리지 않았다 · 그 묶음을 찾았다 · 값 쓰기가 켜져 있다.
  "관계 최고" · "관계 중립"은 지금처럼 목록에서 나라를 골라야 한다.
- **쓸 수 없을 때는 단추 자리에 까닭 한 줄만 보인다**(그 줄에만. 같은 탭의 다른 줄은 그대로다). 글은 돈 탭과 같다:

  | 상황 | 보이는 글 |
  |---|---|
  | 그 묶음을 찾지 못했다 | `<단추 이름> — 이 게임 판에서는 쓸 수 없습니다 (<찾지 못한 것>)` |
  | `SRTOYBOX_WRITE=0` | `<단추 이름> — 값 쓰기를 껐습니다 (SRTOYBOX_WRITE=0)` |
  | 이번 실행에서 값 쓰기가 실패했다 | `<단추 이름> — 값 쓰기가 실패해 껐습니다. 게임을 다시 시작하면 다시 시도합니다.` |
  | 게임을 읽지 못한다(상태 묶음, `SRTOYBOX_READ=0`) | "연구" · "인구·여론" 탭의 그 줄: `<단추 이름> — 게임 상태를 읽을 수 있을 때만 씁니다.` ("외교·영토" 탭은 지금처럼 탭 전체가 그 글이다) |

- **어느 경우에도 내장 치트로 되돌아가지 않는다.** 직접 쓰는 줄은 직접 실행 · 글쇠 방식 · `SRTOYBOX_DIRECT` 와 상관없다.
- 한 번 더 누르기는 없다(지금도 없다). 창 바닥의 안내(글쇠 방식의 "게임의 설정 창이 잠깐 열렸다 닫힙니다")는 그 탭에 내장 치트로 도는 줄이 남아 있는 동안 지금처럼 보인다.

### 로그

| 줄 | 뜻 |
|---|---|
| `값을 더 씁니다 (기술 수준 +0x14CD0 · 세계 시장 여론 +0x14AF4 +0x14AF8 +0x14B10 · 관계 +0x15F10 +0x16F10 전쟁 명분 +0x17F10)` | 새 묶음에서 찾은 것(찾은 묶음만 적는다) |
| `<묶음>을 쓸 수 없습니다 (<무엇>: 서명 3개 가운데 1개)` | 그 묶음을 찾지 못했다. 그 단추만 꺼진다 |
| `값 쓰기: 기술 수준 130 -> 131` | "지식 순위 올리기" |
| `값 쓰기: 세계 시장 여론 최고` | "세계 시장 여론 최고" |
| `값 쓰기: 관계 최고 — 폴란드 (1106)` · `값 쓰기: 관계 중립 — 폴란드 (1106)` | 관계의 두 단추 |
| `값 쓰기 실패 (관계 — 폴란드 (1106), 6칸 가운데 3칸을 쓴 뒤) — 값 쓰기를 끕니다` | 묶음 1 의 규칙 그대로: 실패하면 그 실행에서는 값 쓰기 전체(돈 · 물자 · 유지 포함)를 끈다 |
| `옛 방식(내장 치트)으로 도는 기능이 15개 남아 있습니다 (…)` | 19 → 15 |

창 바닥의 `마지막으로 쓴 값` 은 로그의 `값 쓰기:` 뒤와 같은 글이다(`기술 수준 130 -> 131`, `세계 시장 여론 최고`, `관계 최고 — 폴란드 (1106)`).

### 검증 도구

- `uv run srkit locate`: 새 묶음 셋의 서명 21개와 읽어 낸 자리를 보인다. 묶음 1 처럼 게임 안에서 도는 것과 같은 코드(DLL)를 쓴다.
- `scripts/gamedrive.py peek`: 출력에 기술 수준과 여론의 세 칸을 더한다. `peek <지역 번호>` 는 플레이어와 그 지역 사이의 관계 여섯 칸(내 쪽 셋 · 그 지역 쪽 셋)도 읽는다. 읽기만 한다.

## 오류 처리

| 상황 | 동작 |
|---|---|
| 새 묶음 가운데 하나를 찾지 못함 | 그 단추(들)만 꺼지고 자리에 까닭이 보인다. 로그에 무엇을 못 찾았는지. 돈 · 물자와 다른 단추는 그대로 |
| 상태 묶음을 찾지 못함 | 지금과 같다 — ToyBox 가 게임을 읽지 못하고, 직접 쓰는 줄은 모두 꺼진다 |
| 고른 나라가 쓰기 직전에 없어졌다(다른 판, 병합됨) · 플레이어 자신이다 | 쓰지 않는다. 알림 `그 나라는 이번 판에 없어 쓰지 않았습니다.` |
| 기술 수준이 한도(999)에 닿았다 | 쓰지 않는다. 알림 `기술 수준이 한도(999)라 쓰지 않았습니다.` |
| 읽은 기술 수준이 유한한 수가 아니거나 음수다 | 쓰지 않는다. 알림 `기술 수준을 읽을 수 없어 쓰지 않았습니다.` |
| 게임 밖 · 멀티플레이에서 요청이 왔다 | 버린다(단추가 꺼져 있어 보통은 오지 않는다) |
| 쓸 수 없는 자리이거나 쓴 값이 두 번 다 남지 않았다 | 묶음 1 과 같다: 그 실행에서는 값 쓰기 전체를 끄고 로그에 적는다 |
| 대기열이 가득 찼다 | 묶음 1 과 같다: 받지 않고 알림 |

## 테스트와 검증

**자동 테스트** (게임 없이. 설치된 게임 파일이 있어야 하는 것은 없으면 건너뛴다)

- 설치된 실행 파일에서(TimeDateStamp 가 `0x695377b6` 일 때만 값을 대조):
  - 새 서명 21개가 저마다 실행 구역에 한 번만 맞고, 찾을 것마다 셋이 같은 값을 내고, 값이 이 문서의 표와 같다.
  - **맞은 자리가 모두 치트 코드 밖이다.**
  - **새 찾기가 낸 자리가 치트 본문(`finalexam` · `shelovesme` · `love` · `neutral`)에서 읽은 자리와 같다**(테스트에서만 치트 코드를 본다).
  - `love` 와 `neutral` 의 본문이 같은 여섯 칸을 쓴다(치트가 바뀌면 알아챈다).
- 가짜 이미지: 한 묶음의 서명을 흠 내면 그 묶음만 못 찾고 나머지 묶음과 묶음 1 의 값은 찾는다 / 표 둘이 `0x1000` 보다 가깝거나 칸이 겹치면 그 묶음은 못 찾은 것이다.
- 읽기와 쓰기(가짜 게임 메모리):
  - 기술 수준: 그 칸만 1.0 늘고 둘레의 바이트는 그대로다. 한도 · 유한하지 않은 값에는 쓰지 않는다.
  - 여론: 세 칸만 1.0 이 된다.
  - 관계 최고 · 중립: 정확히 여섯 칸만 바뀐다 — 플레이어 객체의 표 셋에서 그 나라의 칸, 그 나라 객체의 표 셋에서 플레이어의 칸. **다른 지역의 객체, 같은 표의 이웃 칸은 그대로다.**
  - 메뉴 · 멀티플레이 · 일관성이 깨진 상태 · 이번 판에 없는 번호 · 상태가 2 · 3 이 아닌 지역 · 플레이어 자신에는 쓰지 않는다.
  - 플레이어가 바뀌면(다른 객체 · 다른 인덱스) 새 플레이어의 칸에 쓴다.
  - 치트 허용 비트가 그대로다. 읽을 수 없는 포인터에서는 실패로 돌아온다.
- 대기열: 새 요청이 순서대로 쓰인다 / 게임 밖 · 오류 가드 뒤에는 버려진다 / 게임의 함수 안에서 다시 온 타이머에서는 쓰지 않는다 / 실패하면 그 뒤로 쓰지 않는다.
- 창(그린 것의 목록): 네 단추가 제 탭 · 제 자리에 있다 / 눌러도 **명령 처리 함수(가짜)가 불리지 않고 글쇠도 가지 않는다** / 메뉴에서는 꺼진다 /
  묶음을 못 찾은 줄에는 까닭만 있고 단추가 없으며 같은 탭의 다른 줄은 그대로다 / 값 쓰기를 끈 채로는 네 줄 모두 까닭만 있다 / 나라를 고르지 않으면 관계의 두 단추가 꺼진다.
- 기능 표와 [07](../../07-cheats.md)의 대조 테스트는 내장 치트로 도는 15줄에 대해 그대로 통과해야 한다.

**게임 안 확인** (화면 밖 게임, 백그라운드. `SRTOYBOX_HOME` 을 임시 폴더로. 저장하지 않는다. 한 판에서 시간은 3일 넘게 흘리지 않는다. 게임을 띄우는 횟수는 한 번을 목표로 한다)

| # | 한 것 | 볼 것 |
|---|---|---|
| W0 | 새 빌드를 띄운다 | 로그의 `값을 더 씁니다 (…)` 와 `… 15개 남아 있습니다`. 서명 54개가 모두 맞는다 |
| W1 | 메인 메뉴에서 세 탭을 연다 | 네 단추가 꺼져 있다. 눌러도 로그에 새 줄이 없다 |
| W2 | 게임에 들어가 "지식 순위 올리기" | `peek` 의 기술 수준이 1.0 늘었다. 게임 화면의 지식 지수 순위(07 에서 6위 → 1위). **값이 얼마인지 — 기술 수준인가(아직 보지 않은 것 2)** |
| W3 | "세계 시장 여론 최고" | `peek` 의 세 칸이 1.0. 게임 화면의 세계 시장 여론 · 보조금률 · 조약 신뢰도가 07 의 `shelovesme` 와 같다. **누르기 전의 세 값과 화면의 숫자 — 어느 칸이 무엇인가(3)** |
| W4 | 폴란드를 골라 "관계 최고" | `peek 1106` 의 여섯 칸(관계 넷 1.0, 전쟁 명분 둘 0). 게임의 외교 화면에서 두 관계 막대가 가득 차고 전쟁 명분이 0 이다. **누르기 전의 값과 막대 — 어느 표가 어느 막대인가(3)** |
| W5 | "관계 중립" | 여섯 칸이 0. 막대가 절반 |
| W6 | W4 · W5 앞뒤로 다른 나라를 읽는다 | 플레이어 ↔ 다른 나라(예: 덴마크)의 여섯 칸이 그대로다 |
| W7 | W2 ~ W5 내내 | 치트 허용 비트가 0 이다. 게임의 설정 창이 뜨지 않는다. 로그에 그 넷의 `직접 실행` 이 없다 — **전제 확인(1)** |
| W8 | 시간을 "매우 느림"으로 20초 넘게 흘린다 | 게임이 살아 있다. 로그에 예외 · 실패가 없다. 그동안 쓴 값이 얼마나 바뀌는가(4) |
| W9 | "이 나라로 플레이"(옮기지 않은 기능)로 나라를 바꾼 뒤 "세계 시장 여론 최고" | 새 나라의 세 칸이 1.0 이 되고 앞 나라의 값은 그대로다(요구 2). 맨 끝에 한다 — 이 단추가 치트 허용 비트를 켠다 |

`SRTOYBOX_WRITE=0` 과 묶음을 못 찾았을 때의 화면은 자동 테스트로만 본다(게임을 한 번 더 띄워야 한다 — 문서에 그렇게 적는다).

## 설치와 제거

묶음 1 과 같다: 게임 폴더에는 `srtoybox.dll` 하나만 바뀐다(`uv run srkit deploy toybox` — 미리보기로 `갱신: srtoybox.dll` 한 줄임을 본 뒤 `--apply`).

| 게임이 날짜를 넘기는 계산과 쓰기가 겹친다 | 묶음 1 과 같은 위험이고 같은 대비다(쓴 뒤 다시 읽기). 게임에서 그 순간을 본 적은 없다 |
| 게임 업데이트로 자리가 바뀐다 | 묶음마다 따로 꺼진다. `uv run srkit locate` → `sig-mine --offset` 으로 다시 뽑는다 |
| 이 넷만 쓴 판은 게임이 "치트를 쓴 판"으로 알지 못한다 | 묶음 1 에서 사용자가 정한 것과 같다(치트 허용 비트를 건드리지 않는다). 문서의 한계에 적는다 |

## 보완 내역 (2026-10-10, 계획을 쓰고 실행하며)

[구현 계획](../plans/2026-10-10-toybox-stage3-2-values-more.md)대로 끝났다 — **묶음 2 가 끝났다.** 게임에서 본 것은 [10](../../10-toybox.md)의 "확인한 것"(W0 ~ W9),
게임의 안쪽은 [11](../../11-game-internals.md).

**계획을 쓰며 달라진 곳**

- **묶음끼리 자리가 겹치면 두 묶음 다 버린다.** 이 문서는 "하나라도 아니면 그 묶음은 못 찾았다"고만 했다 — 어느 쪽이 엉뚱한 것을 읽었는지 알 수 없다.
  돈 · 물자의 칸과 겹칠 때는 새 묶음만 버린다.
- **여러 칸을 쓰는 요청은 쓰기 전에 모든 칸이 읽기 · 쓰기 쪽인지 먼저 본다.** 자리의 보호 때문에 실패할 때는 한 칸도 쓰지 않는다. 로그의 꼴이 둘이 됐다:
  한 칸도 쓰지 않았으면 `값 쓰기 실패 (관계 — 폴란드 (1106)) — 값 쓰기를 끕니다`, 몇 칸을 쓴 뒤면 `(…, 6칸 가운데 N칸을 쓴 뒤)`.
- **쓰기의 판정에 "그 나라가 없다"를 더했다.** 없는 번호 · 사람도 AI 도 맡지 않은 지역 · 객체가 아는 인덱스가 표의 자리와 다른 것 · 플레이어 자신.
  관계를 쓰는 함수는 수준 −1 … 1 만 받는다(창이 내는 것은 1 과 0 뿐이다).
- **기능 표의 네 줄은 "직접 쓰는 일"의 종류를 갖고 "게임에 넣는 글"은 빈 글이다.** 줄의 수(19)와 순서는 그대로이고 내장 치트로 도는 줄의 수(15)는 따로 센다.
- **기술 수준의 한도(999)는 요청의 대기열(`keeper`)에 뒀다** — 이 문서가 `values` 는 바뀌지 않는다고 했다. 지금 값은 있는 그대로 적는다(`기술 수준 110.002 -> 111.002`).
- **대기열의 문이 바뀌었다.** "돈 · 물자의 값을 쓸 수 있는가"에서 "값 쓰기가 켜져 있는가"로 — 묶음이 서로 기대지 않게. 요청을 받을 때 그 요청이 쓰는 묶음을 본다.
  최소 유지는 돈 · 물자의 자리를 못 찾은 게임에서 쉰다(전과 같다).
- **로그**: `값을 더 씁니다 (…)` 는 찾은 묶음만 ` · ` 로 이어 적는다. `SRTOYBOX_WRITE=0` 이면 `값을 더 쓰지 않습니다 (SRTOYBOX_WRITE=0. …)`. 못 찾은 묶음은
  `기술 수준을 쓸 수 없습니다 (…)` · `세계 시장 여론을 쓸 수 없습니다 (…)` · `관계를 쓸 수 없습니다 (…)`. `맞지 않은 서명: …` 은 찾은 묶음의 것만 적는다.
- **W0 의 "서명 54개가 모두 맞는다"는 로그의 한 줄로는 보이지 않는다.** 게임 안에서는 `맞지 않은 서명` 줄이 없는 것과 `값을 씁니다` · `값을 더 씁니다` 의 자리로 봤고,
  54개가 저마다 한 번 맞는 것은 설치된 실행 파일에 대한 자동 테스트가 본다.
- **이미 있던 화면 테스트 둘을 맞췄다** — "관계 최고"가 더는 게임의 함수를 부르지 않는다: 오류 가드의 경고는 "동맹 맺기"로, 고른 나라가 풀리는 것은 관계의 칸으로 본다.
- **`gamedrive.py peek`**: 새 읽기를 순수 함수(`peek_more`)로 떼어 테스트했다. `peek <지역 번호>` 는 그 지역의 기술 수준 · 여론도 읽는다.
- **`uv run srkit locate`** 는 새 묶음 가운데 하나라도 못 찾으면 종료 코드 1 을 낸다(단추 하나가 꺼지는 것도 "서명이 맞지 않는 것"이다).
