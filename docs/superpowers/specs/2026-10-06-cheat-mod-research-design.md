# 치트·모드 조사와 제작 계획 — 설계

- 작성: 2026-10-06
- 대상 게임: Supreme Ruler 2030, Steam appid `2093410`, build `21347933` (게임 표시 버전 12.1.1360)
- 상태: 설계 승인됨(대화), 문서 검토 대기

표기: **[확인]** 파일·실행 파일·게임 안에서 직접 확인, **[추정]** 정황으로 판단, **[위키]** 공식 위키에 적혀 있으나 이 빌드에서 미확인.

## 목적

사용자가 **자기 싱글플레이에서 쓸 치트 수단**을 갖추는 것이 최종 목적이다. 그 길에 필요한 지식을
원안의 다섯 항목 그대로 조사해 문서로 남긴다.

| 원안 | 내용 |
|---|---|
| ① | 게임 구조 분석 — 국가 / 경제 / 자원 / 산업 / 연구 / 정치 / 외교 / 군사 / 부대 / 장비 / 전쟁 / AI |
| ② | 치트·모드로 수정 가능한 항목 전부 분류 |
| ③ | 실제 데이터 파일 구조 분석 |
| ④ | 「Supreme Ruler 2030 치트/모드 제작 계획」 문서 |
| ⑤ | Steam Workshop 기존 모드 조사, 만들 것과 안 만들 것 분리 |

## 결정 사항 (2026-10-06, 사용자)

1. 최종 목적은 **내 플레이용 치트**다. Workshop 배포나 범용 도구가 목적이 아니다.
2. 범위는 **원안 유지**다. 12개 영역 전체, 전수 분류, Workshop 전수 조사를 모두 한다.
3. 검증은 **전부 나열 + 계층별 검증**이다. 후보는 전부 표에 올리고 항목마다 검증 상태를 붙인다.
   게임 안 검증은 내장 치트 전체와, 수단별 대표 실험 한 건씩만 한다.
4. 접근은 **기계적 목록 + 손으로 쓰는 문서**다. 읽기 전용 도구로 목록을 뽑고 문서는 그 위에 쓴다.
5. 수단별 실험을 위해 **시험 모드를 게임 폴더에 설치했다가 되돌리는 것**을 허락한다.

  <https://supremeruler.fandom.com/wiki/Cheats> (2026-10-06 열람)
- 입력 방법은 게임 진행 중 `Ctrl+Shift+S` → 설정 대화상자 아래 입력란에 `cheat allowcheats` → 이후 치트 입력,
  싱글플레이 전용, 치트 모드는 게임을 끝내야 꺼진다. **[위키]**
- `INI\hotkeys.csv` 에 `0x53, 수정키 4, "Game Settings", <Ctrl> + <Shift> + <S>` 행이 있다. **[확인: 파일]**
- 원안 ②의 예시 아홉 개 가운데 돈·자원·연구·국가 관계·장비 생산·군사력·인구는 내장 치트가 있고,
  **부대 스탯과 GDP 는 내장 치트가 없다.** **[위키]**

- 도구가 훑을 폴더(`INI` `Maps` `Sandbox` `Scenario` `Campaign` `Tutorials` `Common`)의 섹션 종류는 53가지다

### 분류표 형식 (`docs/09`)

한 행이 "바꾸고 싶은 것 하나를 수단 하나로 바꾸는 방법"이다. 같은 항목이 수단마다 여러 행을 가진다.

| 열 | 값 |
|---|---|
| 영역 | ①의 12개 영역 중 하나 |
| 항목 | 예: 국고, 건조 일수, 지지율 |
| 수단 | 내장 치트 / 시나리오 설정(`&&GMC`) / 데이터 표 / 실행 중 훅 / 세이브 편집 / Workshop 기존 모드 |
| 위치 | 치트 명령, 또는 파일·섹션·키(열) |
| 적용 시점 | 진행 중 / 새 게임 시작 때 |
| 대상 | 플레이어만 / 모든 지역 (예: `onedaybuild` 는 AI 도 혜택을 본다 **[위키]**) |
| 검증 | [확인] / [추정] / [위키] |
| 결론 | 그대로 쓴다 / 만든다 / 안 만든다(이유) |

"실행 중 훅"과 "세이브 편집"은 가능성만 적는다. 이 수단의 조사는 범위 밖이므로 전부 [추정]이다.

## 도구: `srkit inventory`

게임 텍스트 데이터에서 섹션·키·열 목록을 기계적으로 뽑는다. 게임 폴더는 읽기만 한다.

- **위치**: `src/srkit/inventory.py`, 명령 등록은 `src/srkit/cli.py`. 줄 읽기는 기존 `srtext`, 디코딩은
  `korean.decode_cp1252` 를 쓴다.
- **훑는 폴더**: `INI` `Maps` `Sandbox` `Scenario` `Campaign` `Tutorials` `Common`.
  `HAPS`(GUI) · `Localize`(현지화) · `Graphics` · `Sounds` · `Cache` · `Misc` 는 훑지 않는다. GUI 와 현지화는 `docs/03` 의 범위다.
- **읽는 줄 모양 세 가지**
  1. 섹션 머리 `&&이름 [번호]`. 줄 처음에 온 것만 센다. `//` 주석 안의 `&&`(`hotkeys.csv` 의 `&&HOTKEYSTEXT`)와
     종료 표시 `&&END` 는 섹션으로 세지 않는다.
  2. 키-값 줄: `키 값`(`CVP`) 과 `키: 값`(`GMC`)
  3. 쉼표 행(`UNITS` 등). 열 이름은 섹션 앞의 `//` 머리 주석에서 얻는다. 머리 주석이 없으면 열 번호만 낸다.
- **출력** (`build/inventory/`, git 제외)

  | 파일 | 열 |
  |---|---|
  | `sections.csv` | 파일, 섹션, 블록 수, 행 수 |
  | `keys.csv` | 섹션, 키, 등장 파일 수, 등장 횟수, 예시 값 |
  | `columns.csv` | 파일, 섹션, 열 번호, 열 이름, 값이 있는 행 수, 예시 값 |
  | `exe-candidates.csv` | 문자열, 이웃한 알려진 키 |
  | `skipped.csv` | 파일, 이유 |

- **실행 파일 대조**: 실행 파일의 ASCII 문자열 가운데 `keys.csv` 의 키와 이웃해 있으면서 어느 파일에도 쓰이지 않은 것을
  `exe-candidates.csv` 에 낸다. 후보일 뿐이므로 문서에는 [추정]으로만 올린다.
- **오류 처리**: 게임 폴더가 없으면 기존 명령과 같은 메시지로 끝낸다. NUL 바이트가 있는 파일(이진)과 읽지 못한 파일은
  멈추지 않고 `skipped.csv` 에 적는다.
- **테스트**: `tests/test_inventory.py`. 합성 자료로 줄 모양 세 가지, 머리 주석 없는 표, 이진 파일 건너뛰기를 검사한다.
  설치본이 있을 때만 도는 테스트 하나가 `CVP` `GMC` `UNITS` 가 결과에 있는지 본다(기존 `conftest.py` 의 건너뛰기 방식).

## 게임 안 검증

모두 `gamedrive.py start` 로 띄운 화면 밖 게임에서 백그라운드로 한다. 저장은 하지 않는다. 근거 스크린샷은
`build/verify/` 에 둔다(git 제외). 사용자가 직접 켠 게임이 떠 있으면 건드리지 않고 기다린다.

### V1 — 내장 치트

1. **입력 경로 확보.** 먼저 메뉴 클릭으로 Game Settings 를 여는 길을 찾는다. 없으면 `gamedrive.py key` 에 조합키를
   보강한다(별도 브랜치, `tests/test_gamedrive.py` 갱신). 둘 다 안 되면 V1 을 "막힘"으로 기록하고 보고한다.
2. `cheat allowcheats` 뒤 치트를 하나씩 넣고 전후 화면을 남긴다.
3. 대상은 실행 파일의 91개 전부다.
   - Galactic Ruler 에서 온 것으로 보이는 명령(`voyager` `enterprise` `q` `adama` `warp9` `charge!` `planetcloud`
     `lightyear` `anomaly` `shielded` `upgrade*`)은 반응 여부만 적는다.
   - **`cheat resettutorial` 은 실행하지 않는다.** Steam 업적을 지운다고 되어 있어 **[위키]** 사용자 계정에 영향을 준다.
   - `stresstest` `meshtest` `killeveryone` 은 맨 마지막에 따로 시험하고, 게임이 멈추면 종료한다.
4. 치트를 켜면 업적이 막히는지는 화면에 표시가 있을 때만 적는다. 없으면 [미확인].

**완료 기준**: 명령마다 [확인: 효과] / [확인: 반응 없음] / [미시험: 이유] 중 하나가 붙는다.

### V2 ~ V4 — 수단별 대표 실험

시험 모드는 설치본의 파일에서 값 하나만 바꿔 `build/probe-<이름>/` 에 만든다. 게임 파일의 사본이므로 저장소에 넣지 않는다.

| 실험 | 바꾸는 것 | 확인하는 곳 | 답하려는 질문 |
|---|---|---|---|
| V2 | `Maps\DATA\DEFAULT.UNIT` 의 장비 하나의 비용 또는 건조 일수 | World 2030 새 게임, 그 장비 정보 창 | 캐시(`Cache\*.SAV`) 재생성 없이 반영되는가 |
| V3 | `Sandbox\World2030.scenario` 의 `&&GMC` `initialfunds` | 로비 설정과 시작 국고 | 시나리오 설정이 반영되는가 |
| V4 | `Maps\W2030.CVP` 의 한 지역 `gdpc` | 그 지역으로 시작한 경제 화면 | 지역 값이 반영되는가 |

**실험 한 번의 절차**: `srkit deploy <시험 모드>` 미리보기로 한글화 모드와 겹치는 파일이 없는지 확인 → `--apply` →
게임 시작 → 관찰 → 게임 종료 → `srkit undeploy <시험 모드> --apply` → 바꿨던 파일이 원본과 같은지 해시로 확인.

**V2 에서 반영되지 않으면**: 캐시가 우선한다는 뜻이다. 재생성 방법을 두 가지까지만 시도한다(시나리오 사본에서 `&&SAV` 를
빼고 원본 로드를 강제 / 모드 경로에 캐시 파일을 두어 가리기). 둘 다 안 되면 `docs/09` 의 미해결 문제로 넘긴다.

**완료 기준**: `docs/01` 의 캐시 관련 [추정] 두 줄이 [확인]으로 바뀌거나, 무엇을 시도했고 왜 확정하지 못했는지가 적힌다.

## Workshop 조사 (`docs/08`)

- 53개 전부를 Workshop 페이지의 제목·설명·태그·필요 DLC·갱신일로 분류한다. 구독하지 않으므로 파일 내용은 보지 않는다.
- 분류: 치트 / 밸런스 / 경제 / 군사·장비 / 국가·시나리오 / 지도 / 그래픽·소리·UI / 도구.
- 설명만으로 기능을 판단할 수 없는 항목은 근거 수준에 "설명 부족"이라고 적는다.
- 조사일을 문서 머리에 적는다. 목록은 시간이 지나면 바뀐다.

## 공개 저장소 제약

- 문서에는 섹션·키·열 **이름**과 직접 쓴 설명만 넣는다. 게임 데이터의 값 덤프는 넣지 않는다(예시 값은 한두 개까지).
- `build/inventory/` `build/probe-*/` `build/verify/` 는 커밋하지 않는다.
- 위키 내용은 옮겨 적지 않고 우리말로 요약해 링크한다(위키는 CC BY-NC-SA).
- 주소(RVA)를 적게 되면 빌드 번호를 함께 적는다.

| 시험 설치가 게임 폴더에 남는다 | 실험마다 `undeploy` 와 해시 확인. 게임 실행 중에는 `deploy` 가 거부한다 |
| 게임 패치로 목록이 낡는다 | 문서 머리에 빌드 번호. `srkit inventory` 를 다시 돌려 차이를 본다 |
