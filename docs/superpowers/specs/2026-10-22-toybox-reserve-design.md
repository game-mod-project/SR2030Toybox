# ToyBox 예비 인원 — `예비 +N` 단추와 최소 유지

- 날짜: 2026-10-22. 게임 build 21347933.
- 상태: 설계 — 사용자의 승인을 기다린다. 사용자가 정한 것: "예비 인원 칸(+0x14B64)에 쓰는 기능(예비 +N 단추와 최소 유지)"(2026-10-22). 나머지는 내 판단(아래 표의 표시).

## 왜

사용자는 인구를 1,000만까지 올려도 유닛 생산 · 시설 건설이 인원 부족으로 멈추는 일을 겪었다. 2026-10-22 의 게임 안 확인에서
**"인구 +100만"은 인구 칸과 인구의 풀에만 닿고, 화면의 현역 · 예비 인원은 그대로**였다(+1,000만에서도 현역 166,700, 예비는 하루 +190 남짓의 자연 증가뿐).
그래서 인원이 모자랄 때 쓸 수 있게 **예비 인원을 직접 늘리는 길**을 둔다.

## 게임에서 알아낸 것 (2026-10-22)

**자리** [확인: 게임 — 화면과 같은 값, 다섯 시점]: 플레이어 지역 객체의 `+0x14B64`(float)가 지휘 패널(아래 줄 ▶ 방패 단추)의 **"예비 인원"**이다(독일 시작 67,211).
옆 칸 `+0x14B60` 은 "현역 인원"이고 날마다 지도에서 다시 센다(현역 인력 `+0x1BB80` 의 사본) — 여기에는 쓰지 않는다.

**게임이 이 칸을 다루는 법** [확인: 정적]:
- **쌓이는 칸이다**: 날마다 도는 함수(`0x778990`, `0x778d17`)가 군 인력이 현역보다 많으면 그 남는 몫을 **더하고**,
  부대의 병력 보충(`0x779520` 안, `0x783566` · `0x78360c`)은 모자란 부대의 몫을 **더하거나 뺀다**. 그 밖의 40곳 남짓(부대 만들기 · 해산 등으로 보인다)도 더하고 뺀다.
- 그래서 **ToyBox 가 더한 값은 국고처럼 남는다**. 내장 치트 `populate` 가 이 칸에 더한 100만이 자정을 넘겨 남았다(3단계 4 의 P3 — 그때는 "셋째 칸"이라 불렀다).
- 유닛 생산 · 병력 보충이 이 칸을 읽고 빼므로(예: `0x846795` — 생산 쪽 함수 `0x8431c0` 이 읽고 견준다), 예비가 바닥나면 생산 · 보충이 멈추는 것으로 본다 [추정 — 게임에서 부족을 재현하지는 못했다].

## 정한 것

| | 정한 것 | 누가 |
|---|---|---|
| 쓰는 곳 | **플레이어 지역 객체의 예비 인원 칸(`+0x14B64`, float) 하나** | 사용자 |
| 기능 | `예비 +N` 단추와 **최소 유지**(정한 값보다 적어지면 올린다) | 사용자 |
| 자리 | `인구·여론` 탭의 `인구 +100만` 아래 | 내 판단 |
| 단추 | 빠른 단추 `+10만` · `+100만` · `+1000만`, 그리고 입력란(사람 수, 기본 100만, 1 ~ 1억)의 `더하기` | 내 판단 |
| 최소 유지 | 체크 + 값(사람 수, 0 ~ 1억). 0.5초마다, 예비가 그 값보다 적으면 그 값으로(국고 · 물자의 최소 유지와 같은 틱 · 같은 꼴) | 내 판단 |
| 저장 | 최소 유지는 저장되는 설정이다: `keep.reserve`(0 / 1) · `keep.reserve.value`(사람 수). 입력란의 값도 `reserve.add` 로 | 내 판단 |
| 끝 | 쓴 결과는 0 이상 1억 이하로 자른다(float 의 정밀도 — 1억대에서는 8명 단위) | 내 판단 |

## 하는 일

- **단추**: 지금 값에 N 을 더해 쓴다. 지금 값이 유한하지 않거나 음수 · 1억을 넘으면 쓰지 않는다. 창 바닥에 `예비 67.2 K -> 1.07 M`.
- **최소 유지**: 켜져 있으면 0.5초마다 지금 값 < 값 이면 값으로 쓴다. 로그에는 이번 실행의 첫 번째만(다른 유지와 같다). 상태 줄의 `유지 중:` 에 `예비` 가 붙는다.
- 메뉴 · 멀티플레이 · 게임 밖에서는 쓰지 않는다(다른 값 쓰기와 같다).
- **쓰는 곳이 하나 는다**: `CLAUDE.md` 와 `game.h` 의 머리말을 함께 고친다. 부르는 게임 함수는 늘지 않는다. 현역 인원 · 인구 · 풀 · 다른 나라에는 쓰지 않는다.
- **주소 찾기**: 예비 칸(`0x14B64`)을 든 서명 셋을 `srkit sig-mine --offset 14b64` 로 뽑는다(서로 다른 함수 42곳에서 후보가 나왔다 — 예: `0x846795` 생산 쪽의 읽기, `0x769c33` 지역 값 다시 셈, `0x7bd42e`).
  ~~더 쓰는 값의 표(MORE)에 새 묶음 `예비`로 둔다~~ — **구현에서 바꿨다(내 판단, 2026-10-22)**: 사회의 품질 등급처럼 배율의 찾기 표(MULTS)에 13번째로 두었다
  (`game_mult_off(MULT_PART_RESERVE)` — 예비 칸 하나만 보면 된다). MORE 표는 묶음 수가 여러 배열 · 로그에 박혀 있어 바꿀 곳이 많았다. 못 찾으면 예비 줄만 꺼지고 까닭을 한 줄 보인다는 것은 같다.
  고른 서명: `0x846795` · `0x769c33` · `0x7bd42e`(설치된 게임에서 셋 다 한 번씩 맞는다). 입력란의 설정 줄은 `reserve.add` 다(`reserve.amount` 는 기존 테스트의 문자열과 겹쳤다).

## 하지 않는 것

- 현역 인원(`+0x14B60` · `+0x1BB80`)은 쓰지 않는다 — 날마다 지도에서 다시 세어 사라진다.
- "인구 +100만"은 그대로 둔다(예비에 함께 더하지 않는다 — 따로 단추를 둔다).
- 부대의 병력 · 생산 대기열에 직접 쓰지 않는다.

## 게임 안에서 볼 것

1. `+100만` — 지휘 패널의 예비 인원이 그만큼 늘고, 자정 두 번 뒤에도 남는가(+ 자연 증가).
2. 최소 유지 500만 — 켜면 바로 500만, 부대 생산 · 보충으로 줄어도 다시 오르는가.
3. **인원 부족의 재현**: 예비가 적은 나라(또는 예비를 써 버린 뒤)에서 생산을 걸어 멈추는지 보고, 예비를 채우면 다시 나아가는지 본다. 재현이 안 되면 그렇다고 적는다.
4. 다른 나라의 예비 · 현역은 그대로, 사용자의 설정 파일은 그대로.
