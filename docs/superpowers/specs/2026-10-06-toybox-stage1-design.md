# ToyBox 1단계 — 게임 안 모드 설정 창과 플레이어 대상 내장 치트 — 설계

- 작성: 2026-10-06
- 대상 게임: Supreme Ruler 2030, Steam appid `2093410`, build `21347933` (게임 표시 버전 12.1.1360)
- 상태: 설계안 승인됨(2026-10-06, 대화). 이 문서의 검토를 기다린다

표기: **[확인]** 파일·실행 파일·게임 안에서 직접 확인, **[추정]** 정황으로 판단, **[위키]** 공식 위키에 적혀 있으나 이 빌드에서 미확인.

## 목적

사용자가 자기 싱글플레이에서 쓸 치트 모드를 **게임 안에서** 다루게 한다. 사용자가 정한 요구는 둘이다.

1. 게임 안에 모드 설정 창이 있고, 모드와 관련된 모든 기능을 그 창에서 설정한다. 설정 파일을 고쳐 다시 빌드하는 방식이 아니다.
2. 설정한 내용은 플레이어가 **지금 플레이 중인 국가에만** 적용된다.

이 문서는 그 첫 단계다: 창을 띄우고, 게임에서 효과를 확인한 내장 치트 가운데 플레이어에게만 닿는 것을 창에서 실행한다.

## 결정 사항 (2026-10-06, 사용자)

| 질문 | 결정 |
|---|---|
| 새 이름의 시나리오가 되는지 게임에서 확인(시험 설치) | 진행 |
| 치트 값을 어느 나라에 넣나 | 게임 안 모드 설정 창에서 모든 기능을 설정한다. 설정은 플레이어가 현재 플레이 중인 국가에만 적용한다 |
| 창을 만드는 방식 | 게임 화면에 그리는 창(훅 DLL + Dear ImGui) |
| 첫 단계의 범위 | 창 + 플레이어 대상 내장 치트 |
| 설계안 | 승인. 구현 중 Dear ImGui 소스를 공식 GitHub 릴리스에서 내려받는 것과, 게임 폴더에 `srtoybox.dll` 을 추가하고 한글화 훅 DLL 을 갱신하는 시험 설치를 포함한다 |

[제작 계획](../../09-cheat-mod-plan.md)은 "실행 중 트레이너(훅 DLL 확장)는 만들지 않는다"고 했다. 위 요구 1·2 는 정적인 시나리오 파일로는
채울 수 없으므로(지역 번호에 고정이고 새 게임을 시작할 때만 적용된다) 그 결정을 뒤집는다. 09 는 이 단계의 문서 작업에서 고친다.

## 설계 전에 확인한 것

- **새 이름의 시나리오는 된다.** [확인: 게임] `Sandbox\World2030.scenario` 의 사본 끝에 `&&CVP 1499` 덮어쓰기를 붙여
  `Sandbox\World2030X.scenario` 로 두고, `Sandbox\World2030X\` 에 `World 2030 Regions.csv` 와 `World2030XStart.csv`(원래 이름은
  `World2030Start.csv`)를 복사했다. 샌드박스 목록에 `World2030X` 로 뜨고(이름표가 없으면 파일 이름), 시작되며, 독일의 1인당 GDP 가 $99,999,
  국고가 $100.00 B 였다. 캐시는 `W2030` 을 그대로 쓴다. 표시 이름은 `Localize\<언어>\LocalText-START.csv` 의 `&&FILETEXT` 에서 온다 [확인: 파일].
  이 단계에서는 쓰지 않는다(요구 2 를 채우지 못한다). 치트가 없는 값의 뒷단계에서 후보로 남긴다.
- **게임 자체 GUI(`HAPS\*.HAPX`)만으로는 새 기능을 만들 수 없다.** [확인: 파일] 개체는 번호가 붙은 엔진 동작(`obAction`)만 부른다.
  단축키 표(`INI\hotkeys.csv`)의 "Game Settings" 도 동작 번호 1115 다.
- **훅이 가로챌 수 있는 지점.** [확인: 실행 파일의 임포트 표] `d3d11.dll` 의 `D3D11CreateDevice`, `USER32` 의 `RegisterClassExA`
  `PeekMessageA` `GetMessageA` `DispatchMessageA` `GetKeyState` `GetAsyncKeyState`, `KERNEL32` 의 `CreateFileA` `CreateFileW` `ReadFile`
  `FindFirstFileA`. 지금 훅(`native/srhook`)은 `WTSAPI32.dll` 프록시로 로드되어 임포트 표만 바꿔 끼운다 — 실행 파일의 주소를 쓰지 않는다.
- **단축키.** [확인: `INI\hotkeys.csv`] `Ctrl+Shift+S`(키 `0x53`, 수정키 값 4)가 게임 설정 창이다. `Ctrl+Shift+T`(`0x54`, 수정키 4)는
  행이 없다(게임이 쓰지 않는다). `F12` 도 비어 있지만 Steam 의 화면 캡처 기본 키다.
- **게임 설정 창은 `ESC` 로 닫힌다.** 같은 단축키를 다시 눌러서는 닫히지 않는다. [확인: 게임]
- **`cheat allowcheats` 는 두 번 넣어도 치트가 켜진 채다.** [확인: 게임] `allowcheats` → `georgew` → `allowcheats` → `georgew` 를 넣자
  국고가 $14.43 B → $34.43 B 가 됐고, 설정 창의 제목은 계속 빨간 "그래, 치트가 필요한가요?"였다.
- **밖에서 넣는 경로는 이미 통한다.** [확인: 게임, 치트 89개] `scripts/gamedrive.py` 는 게임 창에 `WM_KEYDOWN` · `WM_KEYUP` · `WM_CHAR` 를
  보내고, 조합키는 게임 스레드의 키 상태표(`SetKeyboardState`)에 수정키를 눌린 것으로 적어 둔다.
- **명령 처리 코드의 위치.** [확인: 실행 파일, build 21347933] 치트 문자열 91개를 참조하는 코드는 RVA `0x5228b3`–`0x5284c2` 에 모여 있고
  `cheat allowcheats` 는 `0x522330` 근처에서 따로 참조한다. 함수의 인자와 호출 방법은 분석하지 않았다.
- **한글화 빌드가 훅 DLL 을 쥔다.** [확인: `src/srkit/korean.py`] `srkit build` 가 `build/srhook/WTSAPI32.dll` 을 `build/korean/` 에 복사한다.

## 범위

**한다**

- 게임 화면 위에 그리는 모드 설정 창(열고 닫는 단축키, 한글 표시, 입력이 게임으로 새지 않음)
- 창에서 실행하는 기능 16개 — 아래 "기능 목록". 모두 내장 치트이고 게임이 플레이어 국가에만 적용하는 것이다
- 창에서 바꾸는 설정(단축키, 기능마다 마지막에 넣은 값)과 그 저장
- 한글화 훅이 ToyBox DLL 을 불러오는 작은 변경
- 자동 테스트, 화면 밖 게임에서의 확인, 문서

**하지 않는다 (뒷단계)**

| 단계 | 내용 | 왜 뒤인가 |
|---|---|---|
| 2 | 플레이어 국가 식별, 지역을 고르는 치트(지지율·관계·병합 등), 명령 처리 함수의 직접 호출, 게임 진행 중인지 감지 | 실행 파일 분석이 필요하다 |
| 3 | GDP 처럼 내장 치트가 없는 값, 값을 유지하는 토글 | 메모리의 값을 찾아야 한다 |
| 4 | 장비 수치 | 설계가 지역끼리 공유되어 "플레이어만"이 가장 어렵다 |

**하지 않는다 (이 방식에서는 영영)**: 멀티플레이, Workshop 배포(DLL 은 Workshop 으로 보낼 수 없다 — [02](../../02-modding-system.md)).

## 구성

```
게임 프로세스
  WTSAPI32.dll (srhook, 지금 있는 것)  ──(있으면 불러온다)──▶  srtoybox.dll (새로 만든다)
                                                              ├─ 화면 끼어들기   swap chain 의 Present · ResizeBuffers
                                                              ├─ 입력 끼어들기   게임 창의 창 프로시저
                                                              ├─ 창             Dear ImGui (Win32 + DirectX 11 백엔드)
                                                              ├─ 기능 표        이름 · 묶음 · 명령 틀 · 값의 범위
                                                              ├─ 명령 실행기    게임의 설정 창에 치트를 대신 넣는다
                                                              └─ 설정           %APPDATA%\SR2030ToyBox\toybox.ini
```

| 위치 | 내용 |
|---|---|
| `native/srhook/srhook.c` | 로드될 때 스레드 하나를 만들어, 자기 옆에 `srtoybox.dll` 이 있으면 불러오고 `srtoybox_start` 를 부른다. 없으면 아무 일도 없다 |
| `native/srtoybox/` | ToyBox DLL 의 소스(C++17). 파일은 위 여섯 구성 요소대로 나눈다 |
| `native/third_party/imgui/` | Dear ImGui 의 필요한 파일과 `LICENSE.txt`(MIT). 버전을 고정하고 `README.md` 에 버전·출처·받은 날을 적는다 |
| `src/srkit/toybox.py`, `srkit toybox-build` | `build/toybox/srtoybox.dll` 을 만든다. 중간 산출물은 `build/toybox-obj/` 에 둔다(`build/toybox/` 는 게임 루트 구조의 모드 폴더라 DLL 하나만 있어야 한다) |
| `mods/toybox/README.md` | 모드 설명과 설치·제거 방법 |
| `tests/test_toybox.py` | DLL 을 직접 불러 확인하는 테스트(빌드되어 있지 않으면 건너뛴다) |

ToyBox 는 한글화 모드와 **다른 모드**다(`build/toybox/` — 파일 하나를 추가한다). 한 파일은 한 모드만 쥔다는 규칙과 부딪히지 않는다.
다만 불러 주는 쪽이 한글화 모드가 설치하는 `WTSAPI32.dll` 이므로, 이 단계의 ToyBox 는 **한글화 모드가 설치되어 있어야 동작한다.**
한글화 없이 쓰는 불러오기 전용 프록시는 필요해지면 만든다.

### 불러오기 (`srhook`)

- `DllMain` 은 스레드만 만든다(로더 잠금 안에서 `LoadLibrary` 를 부르지 않는다). 스레드가 `GetModuleFileNameW` 로 자기 폴더를 알아내
  `srtoybox.dll` 을 `LoadLibraryW` 로 불러오고, 내보낸 함수 `srtoybox_start` 가 있으면 부른다.
- 환경 변수 `SRTOYBOX=0` 이면 불러오지 않는다(문제가 생겼을 때 끄는 스위치).
- 파일이 깨져 있어도 Windows 의 오류 창이 뜨지 않게 `SetThreadErrorMode(SEM_FAILCRITICALERRORS)` 안에서 불러온다.
- 불러오기에 실패해도 한글 디코딩은 그대로 동작한다. 지금의 `srhook` 테스트(`tests/test_hook.py`)는 DLL 을 파이썬 프로세스에 불러 쓰므로,
  그때는 옆에 `srtoybox.dll` 이 없어 아무 일도 없다.

### 화면 끼어들기

- `srtoybox_start` 는 불러온 스레드에서 돈다. 게임의 창을 기다리지 않는다 — 창은 아래에서 게임의 swap chain 으로부터 얻는다.
- 임시 장치와 swap chain 을 숨긴 창에 만들어 `IDXGISwapChain` 의 가상 함수 표 주소를 얻고, `Present`(8번) · `Present1`(22번) ·
  `ResizeBuffers`(13번) 칸을 바꿔 끼운 뒤 임시 개체를 버린다. 같은 구현 클래스의 swap chain 은 표를 함께 쓰므로 게임의 것도 걸린다.
  실행 파일의 주소는 쓰지 않는다.
- 처음 걸린 `Present` 에서 swap chain 으로부터 장치와 창 핸들(`OutputWindow`)을 얻어 ImGui 를 초기화하고 그 창에 입력 끼어들기를 건다.
  게임이 그리는 창이 곧 주 창이다. 이 프로세스의 창이 아니면 건너뛴다. 그 뒤로는 그 swap chain 에만 그린다.
- `ResizeBuffers` 가 불리면 쥐고 있던 렌더 대상을 놓고, 다음 `Present` 에서 다시 만든다(해상도·전체 화면 전환).

### 입력 끼어들기

- 주 창의 창 프로시저를 `SetWindowLongPtr(GWLP_WNDPROC)` 로 감싼다. 게임 창이 ANSI 창이면 A 쪽 함수로, 유니코드 창이면 W 쪽으로 감싸고
  넘긴다 — 글자 메시지의 변환이 달라지지 않게.
- 감싼 프로시저의 순서: ① 실행기의 타이머면 실행기를 한 걸음 돌리고 삼킨다 ② 명령 실행기가 넣고 있는 동안의 키 메시지는 원래 프로시저로 바로 넘긴다
  ③ 여닫는 단축키면 창을 여닫고 삼킨다 ④ 창이 열려 있으면 ImGui 에 넘기고, 마우스가 창의 사각형 안에 있거나 글자 입력란에 커서가 있으면 삼킨다
  ⑤ 나머지는 원래 프로시저로 넘긴다.
- 마우스가 창 위인지는 창의 사각형으로 직접 가린다(ImGui 의 판단은 한 프레임 늦어, 움직이자마자 누르면 게임으로 샌다).
- 마우스 위치는 창 메시지(`WM_MOUSEMOVE` 와 단추 메시지의 좌표)로만 받는다. `gamedrive.py` 가 보내는 메시지로도 창을 다룰 수 있어야 하기
  때문이다(화면 밖 검증). 같은 이유로 `WM_MOUSELEAVE` 는 ImGui 에 넘기지 않는다(실제 마우스가 창 밖에 있으면 위치가 지워진다).
- 단축키의 수정키는 `GetKeyState` 로 읽는다(사용자의 실제 키, `gamedrive.py` 가 적어 둔 키 상태표 모두 이것으로 읽힌다).

### 창

- 기본 단축키 `Ctrl+Shift+T`. 창의 "설정" 탭에서 바꾼다("단축키 바꾸기"를 누르고 새 조합을 누른다). `ESC` 만 누른 경우는 취소다.
- 글꼴은 Windows 의 맑은 고딕(`%WINDIR%\Fonts\malgun.ttf`)을 실행 중에 읽는다. 없으면 ImGui 기본 글꼴로 뜨고(한글은 깨진다) 로그에 적는다.
  글꼴 파일을 저장소나 모드에 넣지 않는다.
- 탭: 돈 / 물자 / 연구 / 인구·여론 / 부대 / 화면·진행 / 설정. 탭마다 기능이 한 줄씩이다 — 이름, (값이 있으면) 숫자 입력란, 실행 단추, 한 줄 설명.
- 아래쪽 상태 줄: 대기 중인 명령 수와 마지막으로 넣은 명령. 그리고 늘 보이는 안내 두 줄:
  "단추를 누르면 게임의 설정 창이 잠깐 열렸다 닫힙니다." / "게임을 진행하는 중에만 누르십시오. 메뉴나 로비에서는 글자가 다른 곳에 들어갈 수 있습니다."
- 창의 문구는 한국어다. 창의 위치와 크기는 ImGui 가 기억하되 그 파일(`imgui.ini`)도 설정 폴더에 둔다.

| 화면·진행 | 즉시 승리 | `cheat instantwin` | – (한 번 더 눌러 확인) |

**넣지 않는 것과 이유** (요구 2 와 안전):

- 모든 지역 또는 AI 에 닿는 것: `onedaybuild` `allunit` `gates` `devcheat` `endday` `increaseday` `eventnow` `peace` `worldwar` `darren`
  `democracy` `saddam`. 대상을 모르는 `breakground`.
- 불리해지는 것: `depopulate`(인구가 1) `trumpme`(첫 입력은 -$1 T) `sanction` `wmsanction` `shelovesmenot` `saddamme`.
- 지역 번호가 필요한 것: `approval` `love` `hate` `neutral` `annex` `colonize` `novichok` `fight` `treaty` `becomeregion` — 2단계.
- 반응이 없었던 44개, 넣지 않은 `resettutorial`.

이 규칙은 테스트가 지킨다: DLL 이 내놓는 명령은 모두 07 의 표에 있고, 그 줄의 검증이 [확인: 효과], 대상이 "플레이어" 또는 "고른 부대"여야 한다.

### 명령 실행기

단추를 누르면 명령 글자열이 대기열에 들어가고, 실행기가 주 창에 건 10 ms 타이머(창을 가진 스레드)에서 한 걸음씩 처리한다 — 키 상태표는
그 스레드의 것이어야 하고, 화면이 멈춰도 끝까지 돌아야 한다. 한 명령의 걸음:

1. 게임 스레드의 키 상태표에 `Ctrl` · `Shift` 를 눌린 것으로 적고 `WM_KEYDOWN` 을 `Ctrl` · `Shift` · `S` 순서로 보낸다. 50 ms 뒤 `WM_KEYUP` 을
   거꾸로 보내고 상태표를 되돌린다 — 게임 설정 창이 열린다. 되돌릴 때 게임 창이 앞에 있으면 사용자의 실제 키 상태에, 아니면 넣기 전의 값에 맞춘다.
2. `cheat allowcheats` 를 `WM_CHAR` 로 한 글자씩 보내고 `Enter`. 명령마다 매번 보낸다 — 두 번 넣어도 치트가 켜진 채이므로(위 확인)
   새 게임인지 따질 필요가 없다.
3. 명령을 `WM_CHAR` 로 보내고 `Enter`.
4. `ESC` 로 설정 창을 닫는다.

- 메시지는 게임 창에 `PostMessageW` 로 보낸다(`gamedrive.py` 가 밖에서 쓰는, 게임에서 확인된 경로와 같다). 걸음 사이의 간격은
  밀리초로 재서 `gamedrive.py` 가 쓰는 간격(키 누름 50 ms, 글자 사이 30 ms)보다 짧아지지 않게 한다.
- 대기열이 차 있는 동안 창의 단추는 눌리지만 뒤에 줄을 선다. 한 번에 최대 8개까지 받고 넘치면 버린 뒤 상태 줄에 알린다.
- **걸음의 순서는 순수 함수가 만든다**(명령 글자열 → 동작 목록). 실행기는 그 목록을 시간에 맞춰 보낼 뿐이다. 테스트는 이 목록을 본다.
- 명령은 ASCII 만 쓴다(치트 이름과 숫자).

**이 방식의 한계** (창의 안내와 문서에 적는다):

- 단추를 누를 때마다 게임의 설정 창이 잠깐 보인다.
- 게임이 진행 중인지 ToyBox 는 모른다. 메뉴나 로비에서 누르면 글자와 `ESC` 가 그 화면에 들어간다. 저장이나 삭제를 일으키는 입력은 아니지만
  화면이 뒤로 갈 수 있다. 2단계에서 게임 상태를 읽어 막는다.
- 게임이 `Ctrl+Shift+S` 단축키나 치트를 없애면 동작하지 않는다. `srkit cheats-check` 가 그 변화를 알린다.

### 설정

- 위치: `%APPDATA%\SR2030ToyBox\`(`toybox.ini`, `imgui.ini`, `toybox.log`). 게임 폴더와 문서 폴더에는 쓰지 않는다
  (문서 폴더는 이 PC 에서 제어된 폴더 액세스가 막는다).
- 환경 변수 `SRTOYBOX_HOME` 이 있으면 그 폴더를 쓴다(테스트용).
- `toybox.ini` 의 내용: 여닫는 단축키(가상 키 코드와 수정키), 기능마다 마지막에 넣은 값. 값이 범위를 벗어나거나 파일이 깨져 있으면 기본값을 쓴다.
- 값이 바뀌면 바로 저장한다.

## 오류 처리

- 가상 함수 표를 얻지 못하거나, 처음 걸린 swap chain 이 DirectX 11 장치의 것이 아니면 ToyBox 는 아무것도
  하지 않고 `toybox.log` 에 이유를 한 줄 적는다. 게임과 한글화는 그대로다.
- ImGui 초기화에 실패하면 그 뒤로 아무것도 그리지 않고 같은 식으로 끝낸다(끼어든 자리는 원래 함수를 그대로 부르는 채로 둔다).
- 창 프로시저를 감싼 뒤에는 되돌리지 않는다(게임이 끝날 때까지 산다). DLL 을 도중에 내리지 않는다.

## 테스트와 검증

**자동 (pytest, DLL 이 빌드되어 있을 때)**

- 기능 표: 16개, 명령이 서로 다르다, 값이 있는 것은 기본값이 범위 안이다.
- 요구 2 의 규칙: 모든 명령이 07 의 표에서 [확인: 효과]이고 대상이 "플레이어" 또는 "고른 부대"다. 넣지 않기로 한 명령은 하나도 없다.
- 명령 조립: 값이 범위를 벗어나면 잘라 맞춘다. 값이 없는 기능에 값을 줘도 명령은 그대로다.
- 실행기의 동작 목록: 한 명령에 대해 걸음의 순서와 키 코드가 위 "명령 실행기"와 같다.
- 설정: 저장하고 다시 읽으면 같다. 깨진 파일과 범위 밖의 값은 기본값이 된다.
- `srhook`: 옆에 `srtoybox.dll` 이 없어도 지금의 테스트가 그대로 통과한다.

**게임 안 (화면 밖에서 띄운 게임, `scripts/gamedrive.py`)**

| # | 확인 | 기대 |
|---|---|---|
| G1 | `key CTRL+SHIFT+T` | 창이 뜨고 문구가 한글로 보인다. 한 번 더 누르면 닫힌다 |
| G2 | 돈 탭의 "국고 +$10 B" | 재무 패널의 국고가 $10.00 B 늘어난다. 게임 설정 창은 닫혀 있다 |

| G5 | 창 위를 누른다(그 아래에 게임의 단추가 있는 자리) | 게임의 패널이 열리지 않는다 |
| G6 | 창을 닫은 뒤 게임의 단추를 누른다 | 평소처럼 동작한다 |

| G8 | ToyBox 만 제거하고 게임을 띄운다 | 게임과 한글화가 평소대로다 |

**실제 환경 (Steam 으로 띄운 게임, 짧게)**: 화면 크기 창에서 창이 뜨는지, Steam 오버레이와 함께 도는지. 포커스를 가져가므로 꼭 필요한 만큼만 한다.

**게임 폴더**: 시험이 끝나면 `srkit undeploy toybox --apply` 로 빼고, `build/verify/v5/before.sha256` 의 해시 10개가 그대로인지 본다.
한글화 훅 DLL 은 갱신된 채 남는다(한글화 모드의 파일이다).

## 완료 기준

1. `uv run pytest` 가 통과한다(새 테스트 포함. DLL 이 빌드된 환경에서 건너뛰는 것 없이).
2. 화면 밖 게임에서 G1 ~ G8 이 기대대로다. 근거 화면은 `build/verify/toybox/` 에 둔다.
3. Steam 으로 띄운 게임에서 창이 뜬다.
4. ToyBox 를 빼면 게임 폴더의 해시 10개가 그대로이고 한글화가 평소대로다.
5. `docs/10-toybox.md` 가 쓰는 법 · 한계 · 확인한 것을 담고, 09 의 "만들지 않을 것"과 로드맵이 이 방향으로 고쳐져 있다.

## 보완 내역 (2026-10-06, 구현 계획을 쓰며)

승인된 설계의 틀은 그대로이고, 구현 방법을 정하며 본문의 아래 대목을 고쳤다.

- **게임의 창을 기다려 찾지 않는다.** 창은 처음 걸린 `Present` 의 swap chain 에서 얻는다(게임이 그리는 창이 곧 주 창이다). 시작 화면처럼
  먼저 뜨는 다른 창을 잘못 잡을 일이 없고, 60초 기다림도 없어진다.
- **실행기는 `Present` 가 아니라 주 창의 10 ms 타이머에서 돈다.** 키 상태표는 창을 가진 스레드의 것이어야 하고, 화면이 멈춰도 끝까지 돌아야 한다.
- **수정키도 `WM_KEYDOWN` · `WM_KEYUP` 으로 보낸다**(`gamedrive.py` 가 보내는 것과 같은 순서). 되돌릴 때는 게임 창이 앞에 있으면 실제 키 상태에,
  아니면 넣기 전의 값에 맞춘다 — 실행 중에 사용자가 키를 떼거나 눌러도 수정키가 남지 않게.
- **창 프로시저는 게임 창의 문자 방식(A/W)에 맞춰 감싼다.**
- **마우스가 창 위인지는 창의 사각형으로 가리고, `WM_MOUSELEAVE` 는 ImGui 에 넘기지 않는다.**
- **불러오기는 오류 창이 뜨지 않게 한다**(`SetThreadErrorMode`).

## 보완 내역 2 (2026-10-06, 구현하며)

- **Steam 오버레이와 함께 돌 때.** Steam 으로 띄운 게임에서 처음 두 번은 게임이 죽었다(스택 고갈). Steam 오버레이는 진짜 `Present` 의
  머리에 점프를 심어 두고, 가상 함수 표에서 본 ToyBox 의 함수를 "원래 함수"로 불렀다 — ToyBox 가 진짜 함수를 부르면 그 점프를 타고
  오버레이로 되돌아가 서로 맴돌았다. 화면 밖 검증(Steam 을 거치지 않는다)에서는 드러나지 않았다. [확인: 충돌 덤프, 2026-10-06]
- **고친 방법.** 끼어들 때 `dxgi.dll` 파일에서 함수의 원래 첫 명령들을 읽어, 그것을 실행하고 함수의 그 다음 자리로 뛰는 "깨끗한 진입로"를
  만들어 둔다. 재진입이거나, 표의 칸이 우리 것이 아니게 됐거나, 우리 함수의 머리에 누가 점프를 심었으면 그 진입로로 진짜 함수에 바로 간다.
  옮겨도 되는 명령(`push`, `mov` · `lea` 의 레지스터 꼴, `sub rsp`)만 알고, 모르는 명령이 있으면 끼어들지 않는다(ToyBox 만 꺼진다).
  실행 파일의 주소는 여전히 쓰지 않는다 — 읽는 것은 시스템 DLL 이다. 새 외부 소스도 없다.
- **테스트.** `tests/toybox_overlay_probe.py` 가 다른 훅을 흉내 낸다(표의 칸을 바꾸는 훅 두 가지, 함수 머리에 점프를 심는 훅). 테스트가
  실제 장치와 swap chain 을 만들어 `Present` 를 부른다.
- **검증 도구의 한계.** 화면 밖 검증만으로는 Steam 오버레이와의 문제를 볼 수 없다. 화면 끼어들기를 고치면 Steam 으로 띄워 확인한다.
- G3 의 `Ctrl+A` 는 뺐다(검증 도구가 키 상태표를 늦게 되돌려 창이 Ctrl 이 눌린 줄 안다. 숫자 입력란은 누르면 전체가 선택된다).

## 보완 내역 3 (최종 리뷰 뒤, 2026-10-06)

구현을 마친 뒤의 전체 리뷰에서 나온 지적을 고치며 설계에 더해진 것. 쓰는 법과 한계는 [docs/10](../../10-toybox.md)이 기준이다.

- **넣는 동안 사용자의 글쇠를 거른다.** 실행기가 보낸 메시지에는 스캔 코드가 없다는 점으로 가른다. 스캔 코드가 있는 누름과 글자는
  넣는 동안 게임에 넘기지 않는다(뗌 · `Alt` 조합은 넘긴다). 단축키와 설정 창의 입력은 넣는 동안에도 평소대로 처리한다.
- **마우스 좌표는 그리는 면을 기준으로 한다.** 게임 창의 크기와 뒷면의 크기가 다르면 그 비율로 바꿔 ImGui 에 준다. ImGui 의 화면 크기도
  뒷면의 크기로 둔다.
- **깨끗한 진입로의 가정을 끼어들 때 검사한다.** 함수의 첫 14바이트 뒤가 파일과 다르거나, 올라온 DLL 이 디스크의 파일과 다른 판이면
  끼어들지 않는다. `Present` 와 `ResizeBuffers` 는 둘 다 될 때만 표를 고친다.
- **바로잡는 것**: 본문("구성")의 "저장이나 삭제를 일으키는 입력은 아니지만"은 메인 메뉴와 로비 두 화면에서 본 것뿐이다. 다른 화면
  (저장 창 등)에서는 글자와 `Enter` 가 그 화면의 입력이 된다 — 눌러 보지 않았다.
