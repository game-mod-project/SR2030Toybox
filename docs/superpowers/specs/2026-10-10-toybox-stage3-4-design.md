## (가) 인구 · 지지율

**치트가 하는 일** [확인: 정적]

- `cheat populate`(`0x525FD7`): 플레이어 지역 객체의 세 칸 `+0x14B48`(인구) · `+0x14B60` · `+0x14B64` 에 1000000.0 을 더하고, 그 객체로 함수 `0x768A00` 을 부른다.
  그 함수는 지역의 여러 값을 다시 셈하는 큰 함수이고 치트 밖에서는 한 곳(`0x7790BF` — 날마다 도는 함수)에서만 불린다.
- `cheat approval <번호>`(`0x527209`): 그 지역 객체의 `+0x14B04` 에 1.0 을 쓴다(`+0x14B08` 이 1.0 이면 0 을 쓴다). 함수는 부르지 않는다.

**ToyBox 가 하는 일**

- 두 단추는 3단계 2 의 "직접 쓰는 줄"과 같은 길이다(단추 → `keeper` 의 요청 → 창 스레드의 틱 → `game` 의 쓰기). 이름 · 탭 · 자리는 그대로다.
- **인구 +100만**(2026-10-10 에 고쳤다 — 아래 "인구의 원천"): 플레이어의 **인구 칸(`+0x14B48`)과 인구의 풀 칸(`+0x14B58`)**에 1000000 을 더해 쓴다.
  한 칸이라도 유한한 수가 아니거나 음수면 하나도 쓰지 않는다. 치트가 올리던 군 인력 칸(`+0x14B60`)과 셋째 칸(`+0x14B64`)에는 쓰지 않는다.
  **함수 `0x768A00` 은 부르지 않는다**(값 쓰기뿐이다 — 부르는 함수를 늘리지 않는다). 부르지 않아도 결과는 같다 — 내장 치트로 올린 인구도 첫 자정에 되돌아간다 [확인: 게임 — P5].
- **내 나라 지지율 100%**: 플레이어의 한 칸에 1.0 을 쓴다. 치트의 "0 으로 뒤집기"는 옮기지 않는다.
- 자리는 서명으로 찾는다(`locate` 의 표 MORE 에 셋, 서명 9개 — 모두 치트 함수 밖의 코드). 묶음은 둘이다: 인구(두 칸이 모두 맞아야 한다) · 지지율.
  한 묶음을 못 찾으면 그 단추의 자리에 까닭 한 줄만 보인다. 내장 치트로 되돌아가지 않는다.
- **쓰는 곳이 는다**: 플레이어 지역 객체의 인구 2칸(인구 칸과 그 풀) · 국내 지지율 1칸(`game.h` 의 머리말, `CLAUDE.md`). 다른 나라의 객체에는 쓰지 않는다.
- 창 바닥의 글: `인구 82.6 M -> 83.6 M` · `지지율 100%`.

**자동 테스트**: 서명 30개가 설치된 게임에서 한 번씩 맞고 읽어 낸 자리가 치트의 본문과 같다 / 가짜 메모리에서 플레이어의 네 칸만 바뀐다 /
수가 아닌 칸 · 못 찾은 묶음 · 게임 밖에서는 쓰지 않는다 / 창의 두 단추가 글쇠 없이 쓴다. 내장 치트로 도는 줄은 11개가 됐다.

**게임 안 확인 (P1 ~ P5)** — 2026-10-10, 화면 밖에서 띄운 2030 - 세계 · 독일, 저장하지 않음. 값은 `gamedrive.py peek` 으로 봤다.

- **"인구 +100만"은 원래부터 하루짜리다.** 인구와 군 인력은 날마다 다른 곳(도시의 인구 등으로 보인다 [추정])에서 다시 셈해진다. ToyBox 는 내장 치트와 같은 일을 한다 —
  오래 가는 인구 증가는 그 원천을 고쳐야 하고, 이 조각의 범위 밖이다.
- 치트로 올린 판은 인구가 약 3,000 더 남았다(치트가 부르는 함수가 아주 작은 몫을 남기는 것으로 보인다 [추정]). ToyBox 는 그 몫을 주지 않는다.
- 셋째 칸(`+0x14B64`)에 남는 100만이 무엇에 닿는지는 모른다(치트도 같은 것을 남긴다).
- 국고가 이틀에 ToyBox 판 +15.45 B, 치트만 넣은 판 +7.83 B 였다. 차이는 지지율을 1.0 으로 올린 것 때문으로 보인다 [추정 — 가르지 않았다].

### 인구의 원천 (2026-10-10, 사용자가 조사를 청했다)

**게임이 인구를 셈하는 법** [확인: 정적 — 날마다 도는 함수(`0x7789D4` 부근, 민간 인구의 칸을 `0x778D27` 에서 읽고 `0x778DF1` 에서 되쓴다), 그리고 게임 — P6]

- 자정마다 지역마다: `인구(+0x14B48) = 민간 인구(+0x1BB7C) + 풀(+0x14B58) + 현역 인력(+0x1BB80)`, `군 인력(+0x14B60) = +0x1BB80`.
  독일 · 폴란드의 세 시점에서 이 합이 인구 칸과 float 의 정밀도 안에서 맞았다.
- 민간 인구와 현역 인력은 날마다 0 에서 다시 쌓인다(지도의 칸을 돌며 주인 지역에 더한다 — `0x779520`). 그래서 인구 칸 · 군 인력 칸에 더한 것은 첫 자정에 사라진다.
- **풀(`+0x14B58`)은 다시 쌓이지 않는다.** 자연 증가가 날마다 이 칸에 더해진다(독일 하루 약 +3,040 — 그동안 민간 인구는 한 자리도 안 변했다). 시작 값은 3,632.
  화면의 무엇인지는 찾지 못했다("칸에 배치되지 않은 인구"쯤으로 보인다 [추정]). 부대 관련 코드 여러 곳이 이 칸을 고친다.

**실험 P6** — 분석용 스크립트로 독일의 풀에 100만을 더했다(내장 치트 · ToyBox 단추 없이. 저장하지 않는 판)

| 시점 | 인구 | 민간 인구 | 풀 | 현역 인력 |
|---|---|---|---|---|
| 기준 (Mar 15 00:01) | 82,615,760 | 82,445,424 | 3,632 | 166,700 |
| 더한 직후 ~ 자정 전 | 82,615,760 | 82,445,424 | 1,003,632 | 166,700 |
| 첫 자정 뒤 | **83,618,792** | 82,445,424 | 1,006,669 | 166,700 |
| 둘째 자정 뒤 | **83,621,840** | 82,445,424 | 1,009,712 | 166,700 |

- 더한 100만이 자정을 두 번 넘겨도 인구에 남았다. 폴란드는 다른 판들과 같은 값이었다. 오류는 없었다.
- 풀에만 더하면 화면의 인구는 다음 자정에야 바뀐다 — 그래서 인구 칸에도 함께 더한다(사용자가 정했다: "풀 + 인구 칸").
- 부작용으로 본 것: 국고의 이틀 증가가 +7.95 B(아무것도 안 한 판 +7.83 B. 정지한 시각이 달라 엄밀한 비교는 아니다). 실업률 · 군 인력 · 지지율의 흐름은 그대로였다.
- 보지 않은 것: 사흘 넘게 · 달이 바뀐 뒤에도 남는가, 풀의 인구가 도시 인구 · 징집으로 흘러가는가, ToyBox 의 단추로 쓴 판에서 메모리의 값을 잰 것(아래 P7 은 사용자가 화면으로 봤다).

**게임 안 확인 P7** — **사용자가 직접 플레이하는 판에서 봤다(2026-10-10): 단추로 올린 인구가 유지된다.** 메모리의 값(`peek`) · 군 인력 · 다른 나라는 이 판에서 따로 재지 않았다. 보려던 것: "인구 +100만"을 누른다 → 화면의 인구가 바로 +100만(패널을 누르면) · `peek` 의 `people` 두 칸이 +100만 →
자정을 넘긴다 → 인구가 그대로(+ 자연 증가) · 풀도 그대로 · 군 인력은 처음 그대로 · 다른 나라는 그대로.

## (나) 외교 · 영토 — 설계 전

동맹(`treaty`) · 병합(`annex`) · 식민지화(`colonize`) · 지도자 제거(`novichok`) · 전쟁 붙이기(`fight`) · 이 나라로 플레이(`becomeregion`).
어떤 함수를 어떤 인자로 부를지는 기능마다 여기에 적어 사용자가 정한다.

> **정정(2026-10-10)**: 이 문서의 주소 가운데 처음 적은 것들은 분석 스크립트가 같은 폴더의 `MapEditor.exe` 를 읽어 틀렸다(엔진 코드를 함께 써서 구조체의 자리는 같았다 —
> 서명과 게임 안 실험은 `SupremeRuler2030.exe` 기준이라 그대로다). 아래와 위의 주소는 게임 실행 파일로 다시 읽어 바로잡은 것이다. 분석할 때는 `srkit.toybox.EXE_NAME` 을 쓴다.

**치트의 본문을 훑은 것** [확인: 정적 — `SupremeRuler2030.exe` 의 치트 처리 함수(`0x522330` ~ `0x5284FD`) 안. 인자의 뜻은 대부분 [추정]이다]

| 기능 | 치트가 하는 일 | 부르는 함수 |
|---|---|---|
| 식민지화 | 대상 지역의 인덱스를 얻어 한 번 부른다 | `0x771FB0`(플레이어의 지역 객체, 대상의 인덱스, 1) |
| 병합 | **지도의 모든 칸을 돌며**(지도 객체 `[0x1829020]` 의 `+0x88` 이 칸 수) 주인이 대상인 칸마다 부른다 | `0x741530`(칸의 참조, 플레이어의 인덱스, 0, 0, 0, 0) — 칸 수만큼 |
| 이 나라로 플레이 | 전역 넷(플레이어 인덱스 `0x18294E0` · `0x18294EC`, 플레이어 포인터 `0x18295F8` · `0x1829600`)을 고쳐 쓰고 한 번 부른다 | `0x6E8D50`(그 지역 객체, 0) |
| 동맹 맺기 | 지도에서 고른 나라에 대해 같은 함수를 여러 번 부른다(조약의 종류마다) | `0x70CBD0` × 여러 번 |
| 지도자 제거 | 두 함수를 차례로 부른다 | `0x6E7AC0`, `0x6EF3C0` |
| 전쟁 붙이기 | 두 나라의 객체를 얻어 한 번 부른다 | `0x6FEB60` |

- [3단계 1](2026-10-09-toybox-stage3-1-design.md)의 표가 적은 주소(병합 `0x741530` · 식민지화 `0x771FB0` · 나라 바꾸기 `0x6E8D50` · 조약 `0x70CBD0`)와 같다.
- 쉬운 순서로 보이는 것: 식민지화(한 번 부른다) → 전쟁 붙이기 → 이 나라로 플레이(전역 넷을 쓴다 — 쓰는 곳이 는다) → 지도자 제거 → 동맹 → 병합(칸마다 부른다 — 가장 무겁다).
- 기능마다 정할 것: 그 함수가 치트 밖에서도 불리는가(게임 자신의 함수인가), 인자의 뜻, 서명으로 찾을 자리, 멀티플레이 · 게임 밖에서의 가드, 게임 안 확인 항목.

### 식민지화 — 사용자가 승인했다(2026-10-10). 끝(게임 안 확인 C0 ~ C3)

- **함수** `0x771FB0(지역 객체 A, 지역 인덱스 b, 깃발)` [확인: 정적]. 치트 밖의 열 곳에서 게임이 스스로 부른다(깃발 1 이 넷, 0 이 여섯) — 게임 자신의 함수다.
  치트는 `(플레이어의 지역 객체, 고른 나라의 인덱스, 1)` 로 한 번 부른다. 인자의 뜻(A 가 종주국, b 가 식민지가 되는 쪽, 깃발)은 [추정]이다 —
  07 의 기록(고른 나라가 내 식민지이자 동맹국이 된다)과 맞는다.
- **ToyBox 가 하는 것**: 같은 인자로 한 번 부른다. 창 스레드에서, 구조적 예외 가드 안에서, "게임의 함수 안" 깃발을 세우고(연구의 "다시 셈"과 같은 길).
  부르기 전에 본다: 진행 중 · 멀티플레이가 아니다 · 오류 가드가 걸리지 않았다 · 고른 나라가 이번 판에 있고 플레이어가 아니다. 한 번 더 누르기(지금 그대로).
- **주소 찾기**: 그 함수를 부르는 자리의 서명 셋(치트 함수 밖 — `sig-mine 771fb0 --back 2`). 못 찾으면 그 단추의 자리에 까닭 한 줄. 내장 치트로 되돌아가지 않는다.
- **부르는 함수가 는다**: "효과를 다시 셈" 다음의 둘째 함수다(`game.h` 의 머리말 · `CLAUDE.md`).
- **구현**: `locate` 의 새 표 ACTS(부르는 게임의 함수 — 서명 셋이 **모두** 한 번씩 맞고 같은 주소를 내며 그 주소가 함수의 시작이어야 한다),
  `game_colonize`(가드 안의 호출), `keeper` 의 따로 선 줄(틱마다 하나, 잠금을 놓고), 단추는 직접 쓰는 줄이 됐다(둘째 누름에 실행).
  값 쓰기를 끈 실행(`SRTOYBOX_WRITE=0`)에서는 이 단추도 꺼진다. 함수 안에서 예외가 나면 오류 가드가 걸린다(`식민지화하는 중 오류가 났습니다. …`).
