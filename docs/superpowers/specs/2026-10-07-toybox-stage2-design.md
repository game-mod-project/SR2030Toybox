## 목적

1단계의 ToyBox 는 게임을 들여다보지 못한다: 단추를 누르면 게임의 설정 창에 글쇠를 대신 넣을 뿐이고, 게임이 진행 중인지도, 플레이어가
어느 나라인지도 모른다. 2단계는 ToyBox 가 **게임의 상태를 읽고**, 치트를 **게임의 명령 처리 함수에 직접 넘기고**, **나라를 골라 쓰는 치트**를 더한다.

요구는 1단계와 같다(사용자, 2026-10-06): 모든 기능은 게임 안의 설정 창에서, 적용은 플레이어가 지금 플레이 중인 국가에만.

## 설계 전에 확인한 것

조사는 둘이다. (가) 실행 파일의 정적 분석 — 파일을 읽어 MSVC 의 `dumpbin` 과 Python 표준 라이브러리로 봤다. (나) 화면 밖에서 띄운 게임
(`scripts/gamedrive.py start`, 2030 - 세계, 독일)의 메모리를 밖에서 **읽기만** 했다(`ReadProcessMemory`). 게임 폴더에는 쓰지 않았다.

### 명령 처리 함수 [확인: 정적]

- 게임 설정 창의 입력줄이 부르는 함수는 **하나**다: RVA `0x522330` – `0x5284fd`(25,037 바이트). 치트 문자열 91개를 모두 이 함수가 참조한다.
  (1단계 문서의 "RVA `0x5228b3` – `0x5284c2`"는 이 함수의 `.pdata` 조각이었다. 큰 함수는 조각이 여럿이고 chained unwind 로 묶인다.)
- 모양은 `void f(void *this /*RCX*/, const char *line /*RDX*/)`. 길이 인자와 반환값이 없다. `line` 은 `cheat ` 까지 포함한 입력줄 전체다.
- `.text` 전체에서 이 함수를 부르는 곳은 **`0x6649af` 한 곳**이고(`call rel32`), 바로 앞에서 `lea rcx,[0x1764310]` 으로 `this` 를 채운다.
  `this` 는 어디서 읽어 오는 포인터가 아니라 **정적 전역 객체 `0x1764310` 의 주소 자체**다. 함수 주소를 포인터로 들고 있는 데이터는 없다(가상 호출이 아니다).
- 인자 없는 치트 66개는 `strcmp`(줄 전체가 같아야 한다), 인자를 받는 25개는 `strstr` 로 맞춘 뒤 **마지막 공백 뒤**를 `strtol` 한다. 모두 소문자 그대로여야 한다.
- 함수 머리의 검사는 **멀티플레이 표시**(byte `0xf19634`) 하나다. 서 있으면 아무것도 하지 않는다.
  "게임이 올라와 있는가"는 검사하지 않고, 플레이어 포인터를 NULL 검사 없이 65번 역참조한다 — **게임 밖에서 직접 부르면 안 된다.**
  설정 창이 열려 있어야 한다는 검사도 없다.
- 게임의 메시지 루프(`WinMain`)와 창 프로시저, 프레임 갱신이 한 스레드에서 번갈아 돈다. ToyBox 의 타이머는 창 프로시저 안에서 돈다 — 게임이 이 함수를 부르는 자리와 같은 스레드다.
- 실행 파일은 재배치 정보가 없어 항상 `0x140000000` 에 올라온다. 그래도 주소는 `GetModuleHandle(NULL)` 에서 얻는다.

### 실행 중에 읽은 값 [확인: 실행]

| 때 | 프로그램 상태 | 모드 상태 | 플레이어 포인터 | 치트 비트 |
|---|---|---|---|---|
| 뜨는 중 · 메인 메뉴 | 3 | 1 | NULL | 0 |
| 로비(샌드박스 선택) | 3 | 1 | NULL (인덱스는 이미 176) | 0 |
| "시작"을 누르고 2초 뒤 ~ 게임 안 | 1 | 2 | 있다(번호 1499) | 0 |
| 게임의 설정 창 · 게임 메뉴가 열려 있을 때 | 1 | 2 | 그대로 | 그대로 |
| `cheat allowcheats` 뒤 | 1 | 2 | 그대로 | **1** |
| `cheat becomeregion 1106` 뒤 | 1 | 2 | 바뀐다(인덱스 141, 번호 1106, 국고 10.69 B) | 1 |
| `cheat becomeregion 1499` 뒤 | 1 | 2 | 처음 값으로 돌아온다 | 1 |
| 게임에서 메인 메뉴로 나온 뒤 | 3 | 1 | **NULL** (인덱스는 176 이 남는다) | **0** |

- 진행 중의 판정은 `모드 상태 == 2 && 프로그램 상태 == 1 && 플레이어 포인터 != NULL` 로 충분해 보인다. 인덱스는 게임 밖에서 낡은 값이 남으므로 판정에 쓰지 않는다.
- "시작"을 누른 직후(불러오는 화면)에도 값은 이미 진행 중이다. 그때 치트가 듣는지는 보지 않았다.
- 치트 허용은 메뉴로 나오면 꺼진다. 게임에 들어갈 때마다 다시 켜야 한다.

### 아직 보지 않은 것

1. ToyBox 의 타이머에서 이 함수를 실제로 불렀을 때의 결과(국고 +$10 B), 설정 창이 닫힌 채 불러도 화면이 갱신되는지.
2. 인자 없는 지역 치트가 "지도에서 고른 지역"을 쓰는지(`[0x1764320]` 을 읽는 코드는 있다 [확인: 정적], 뜻은 [추정]).
3. 멀티플레이 로비에서 멀티플레이 표시가 1 이 되는지(멀티플레이는 띄워 보지 않는다 — 범위 밖).
4. 치트 허용 비트가 서 있으면 Steam 업적을 주는 호출 19곳이 건너뛰어지는 것으로 읽힌다 [추정: 코드의 모양만 봤다].
5. 다른 빌드에서 주소 찾기가 되는지(이 빌드 하나만 있다).

## 범위

**넣는 것**

1. 주소 찾기: 올라와 있는 실행 파일에서 위의 주소들을 문자열을 닻으로 찾는다. 주소를 코드에 적지 않는다.
2. 게임 상태 읽기: 진행 중 여부, 플레이어 지역의 번호, 이번 게임에 있는 지역의 목록, 멀티플레이 표시.
3. 직접 실행과 자동 전환, 오류 가드.
4. 게임 밖 · 멀티플레이에서 단추 끄기.
5. 나라 이름표와 나라 고르기(목록 · 검색).
6. 치트: 내 나라 지지율 / 관계 최고 · 중립 / 동맹 / 병합 · 식민지화 / 지도자 제거 / 전쟁 붙이기 / 이 나라로 플레이.
7. 점검 명령 `uv run srkit locate`.
8. 문서.

**넣지 않는 것**

- 게임의 메모리에 **값을 쓰는 것**(국고 · GDP 를 직접 고치기, 치트 비트를 직접 세우기). 이 단계에서 ToyBox 가 게임에 가하는 변화는 게임의 명령 처리 함수를 거친 것뿐이다. 3단계.
- 값을 유지하는 토글, 장비 수치. 3 · 4단계.
- `cheat hate`(불리해진다), `liberate` · `revolt`(07 에서 반응이 없었다), 인자를 시험하지 않은 `treaty <번호>`.
- 멀티플레이.
- 지도에서 고른 나라를 창에 보여 주기(게임의 "고른 지역"을 읽는 것은 [추정]이다).

## 구성

```
srtoybox.dll
  locate   ── 실행 파일의 이미지에서 주소 찾기 (순수 함수)
  game     ── 찾은 주소로 게임 상태 읽기 (읽기만)
  regions  ── 지역 번호 → 이름 (빌드할 때 번역 테이블에서 만든 표)
  runner   ── 실행 방식 둘: 직접 실행 / 글쇠 넣기(1단계 그대로)
  ui       ── 상태 줄, "외교·영토" 탭, 나라 고르기
```

### 주소 찾기 (`locate`)

입력은 "RVA 대로 펼쳐진 실행 파일의 바이트"(올라와 있는 모듈, 또는 테스트가 파일에서 만든 것)와 그 크기. 출력은 주소 묶음 또는 실패한 까닭.

절차(이 빌드에서 주소를 적어 넣지 않고 같은 값을 다시 얻었다 [확인: 정적]):

| 찾을 것 | 절차 |
|---|---|
| 명령 처리 함수 | `"cheat allowcheats\0"` 를 찾는다 → 그것을 가리키는 `lea r,[rip+d]` → 그 자리가 든 `.pdata` 항목 → chained unwind 를 뿌리까지 따라간 시작 |
| 멀티플레이 표시 | 함수 머리의 `80 3D d32 00` (`cmp byte ptr [rip+d],0`) |
| 옵션 묶음 | 머리의 `83 0D d32 40` (`or dword ptr [rip+d],40h`) |
| 호출 자리와 `this` | 함수 시작을 목표로 하는 `E8 rel32` → 바로 앞의 `48 8D 0D d32` (`lea rcx,[rip+d]`) |
| 플레이어 포인터 | `"cheat georgew"` 의 `lea` 뒤 0x40 바이트 안의 `48 8B 05 d32 F2 0F 10 80 off32` (`off32` 는 국고의 자리 — 대조에만 쓴다) |
| 플레이어 인덱스 · 지역 표 | `"cheat populate"` 의 `lea` 뒤의 `48 63 05 d32 4C 8D 3D d32` 와 `49 8B 8C C7 off32` (월드 객체 + `off32` = 지역 표) |
| 프로그램 상태 | 호출 자리가 든 함수(뿌리)의 머리 0x40 바이트 안의 `83 3D d32 06` |
| 모드 상태 | `C7 05 d32 02 00 00 00 C7 05 d32 01 00 00 00` — 둘째 주소가 위의 프로그램 상태와 같아야 한다 |

"찾았다"의 조건(하나라도 어긋나면 실패):

1. 닻 문자열이 정확히 1개이고 그것을 가리키는 `lea` 가 1곳이다.
2. 함수 시작을 부르는 `call` 이 정확히 1곳이고 바로 앞이 `lea rcx,[rip+d]` 다.
3. 함수 머리에서 `cmp byte` 와 `or dword …,40h` 가 둘 다 나온다.
4. `georgew` 와 `georgeww` 가 같은 플레이어 포인터 주소를 준다.
5. `becomeregion` 이 쓰는 첫 dword(`0F B7 4A 04 33 D2 89 0D d32 89 0D d32 48 63 C1`)가 `populate` 가 읽는 인덱스와 같다.
6. 모드 상태 서명이 1곳이고 그 둘째 주소가 프로그램 상태와 같다.
7. 찾은 주소가 모두 이미지 안에 있다.

지역 객체 안의 자리(`+0`, `+4`, `+8`)는 서명으로 찾을 수 없다. 이 값들은 코드에 상수로 두고, **읽을 때마다** 아래 "일관성"으로 거른다.

### 게임 상태 읽기 (`game`)

주소 묶음을 받아 상태를 돌려준다. 메모리를 직접 역참조하지 않고 **안전한 읽기**(자기 프로세스에 대한 `ReadProcessMemory`)로 읽는다 — 낡은 포인터를 만나도 죽지 않는다.

```
상태:
  known      주소를 찾았는가
  in_game    모드 상태 == 2 && 프로그램 상태 == 1 && 플레이어 포인터 != NULL && 일관성
  multiplayer
  cheats_on  옵션 묶음 & 0x40
  player     플레이어 지역의 번호 (in_game 일 때만)
  regions    이번 게임에 있는 지역의 번호들: 표[1 .. 지역 수] 가운데 객체[+0] != 0 인 것의 객체[+8]
             (구현하며 "객체[+0] 이 2 또는 3 인 것"으로 좁혔다 — 끝의 "보완 내역")
```

일관성(모두 참이어야 `in_game`): 플레이어 인덱스가 1 ~ 1023 이다 / 표[인덱스] == 플레이어 포인터 / 객체[+4] == 인덱스 / 0 < 객체[+8] < 12900 / 객체[+0] != 0 / 0 < 지역 수 < 1024.
주소는 찾았는데 일관성이 깨지면 `in_game` 이 아니라 **`known` 을 거짓으로** 본다(구조가 바뀐 빌드일 수 있다 → 글쇠 방식).
다만 게임 밖(모드 상태 != 2 이거나 포인터가 NULL)은 일관성을 보지 않고 "진행 중이 아니다"다.

상태는 창이 보이는 동안 프레임마다, 그리고 명령을 실행하기 직전에 읽는다. 값을 붙들어 두지 않는다(`becomeregion` 이 플레이어를 바꾼다).

### 실행 (`runner`)

| 방식 | 언제 | 하는 일 |
|---|---|---|
| 직접 실행 | `known` 이다 | 창 스레드의 타이머에서: 상태를 다시 읽는다 → `in_game` 이고 멀티플레이가 아니면, 치트 허용 비트가 꺼져 있을 때 `f(this, "cheat allowcheats")`, 이어서 `f(this, 명령)` |
| 글쇠 넣기 | `known` 이 아니다(주소를 못 찾았다 · 일관성이 깨졌다), 또는 환경 변수 `SRTOYBOX_DIRECT=0` | 1단계 그대로 |
| 실행하지 않음 | 오류 가드가 한 번 걸린 뒤(게임을 다시 띄울 때까지) | 아래 |

- 직접 실행은 한 번에 끝난다(대기열의 명령 하나 = 타이머 한 틱). 글쇠가 가지 않으므로 넣는 동안 사용자의 글쇠를 거를 일도 없다.
- 치트 허용은 게임의 함수로 켠다(비트를 직접 세우지 않는다).
- **오류 가드**: 함수 호출을 구조적 예외 처리(`__try` / `__except`)로 감싼다. 예외가 나면 (가) 로그에 예외 코드와 명령을 적고 (나) 이 실행에서 직접 실행을 끄고
  (다) 창에 "직접 실행 중 오류가 났습니다. 저장하지 말고 게임을 다시 시작하십시오."를 계속 띄운다. 게임의 상태가 어긋났을 수 있으므로 그 뒤로는
  게임을 다시 띄울 때까지 **글쇠 방식으로도 실행하지 않는다**(승인된 설계안의 "직접 실행을 끈다"를 한 걸음 더 조인 것이다 — 어긋났을지 모르는 판에 치트를 더 넣지 않는다).
- `known` 인데 `in_game` 이 아니거나 멀티플레이면 **실행하지 않는다**(두 방식 모두). 단추가 꺼져 있으므로 보통은 닿지 않고, 눌린 뒤 상태가 바뀐 경우를 막는 것이다.
  대기열에 남은 명령은 버리고 창에 "게임이 진행 중이 아니어서 실행하지 않았습니다"를 적는다.
- `known` 이 아니면 1단계와 똑같이 동작한다(진행 중인지 모른 채 글쇠를 넣는다. 창의 안내문도 그대로).

### 나라 이름표 (`regions`)

- `srkit toybox-build` 가 `mods/korean/translation/localtext-regions.csv` 의 `REGIONTEXT|<번호>|0` 행에서 `번호, 한글 이름, 영문 이름` 표를 만들어
  `build/toybox-obj/` 에 두고 DLL 에 넣는다. 모드의 파일은 계속 DLL 하나다. 생성물은 저장소에 넣지 않는다(원본이 저장소의 번역 테이블이다).
- `status` 가 번역되지 않은 행은 영문 이름을 한글 자리에 쓴다. 표에 없는 번호는 `#<번호>` 로 보인다.

### 창 (`ui`)

- **상태 줄**(탭 위): `플레이 중: 독일 (1499)` / `게임을 진행 중이 아닙니다 — 단추가 꺼져 있습니다` / `멀티플레이에서는 동작하지 않습니다` /
  `게임 상태를 읽을 수 없습니다 — 글쇠 방식으로 동작합니다`(이때는 1단계의 안내문 두 줄도 그대로).
- **단추 끄기**: `known` 이고 (`in_game` 이 아니거나 멀티플레이)면 실행 단추를 모두 끈다. 설정 탭은 그대로 쓴다.
- **"인구·여론" 탭**에 `내 나라 지지율 100%` — `cheat approval <플레이어 번호>`. `known` 이 아니면 이 단추는 꺼 둔다(번호를 모른다).
- **새 탭 "외교·영토"** — `known` 이 아니면 탭 안에 "게임 상태를 읽을 수 있을 때만 씁니다"만 보인다.
  - 나라 고르기: 검색란 + 목록. 목록은 이번 게임에 있는 지역 가운데 플레이어 자신을 뺀 것, 한글 이름순. 검색은 한글 이름 · 영문 이름 · 번호의 부분 일치(영문은 대소문자 무시).
    고른 나라는 목록 위에 `고른 나라: 폴란드 (1106)` 로 보인다. 고른 나라가 이번 게임에 없게 되면(다른 게임을 시작했다) 선택을 지운다.
  - 단추:

| 창의 이름 | 넣는 명령 | 대상 | 한 번 더 누르기 |
|---|---|---|---|
| 관계 최고 | `cheat love <번호>` | 목록에서 고른 나라 | – |
| 관계 중립 | `cheat neutral <번호>` | 목록에서 고른 나라 | – |
| 병합 | `cheat annex <번호>` | 목록에서 고른 나라 | 예 |
| 식민지화 | `cheat colonize <번호>` | 목록에서 고른 나라 | 예 |
| 지도자 제거 | `cheat novichok <번호>` | 목록에서 고른 나라 | 예 |
| 이 나라로 플레이 | `cheat becomeregion <번호>` | 목록에서 고른 나라 | 예 |
| 동맹 맺기 | `cheat treaty` | **지도에서 고른 나라** | – |
| 전쟁 붙이기 | `cheat fight <번호>` | 지도에서 고른 나라 ↔ 목록에서 고른 나라 | 예 |

  - `treaty` 와 `fight` 는 게임이 지도에서 고른 나라를 대상으로 삼는다(07 에서 그렇게 확인했다). 부대 탭처럼 "지도에서 나라를 고른 뒤 누른다"고 적는다.
  - 목록의 나라가 필요한 단추는 나라를 고르기 전에는 꺼져 있다.
- **한글 검색 입력**: 게임 창은 ANSI 창이라 [확인: 정적 — 메시지 루프가 `GetMessageA` · `DispatchMessageA` 다] 한글 한 글자가 `WM_CHAR` 두 번(CP949 의 앞 · 뒤 바이트)으로 온다.
  ImGui 의 Win32 백엔드는 한 바이트씩 바꾸므로 깨진다. 설정 창의 입력란에 초점이 있을 때 앞 바이트를 들고 있다가 뒤 바이트와 합쳐 한 글자로 넘긴다.
  게임에서 입력기로 쳐 보는 것은 검증 도구로 할 수 없다 — 바이트 두 개를 보내 확인하고, 실제 입력기는 [추정]으로 적는다.

### 기능 표

1단계의 기능 표(`features`)에 "대상" 열을 더한다: 없음 / 플레이어 번호(자동) / 목록에서 고른 나라 / 값(1단계의 숫자 입력). 한 기능의 인자는 하나다.
`fight` 의 "지도에서 고른 나라"는 게임이 읽는 것이라 인자가 아니다.
자동 테스트가 이 표를 07 과 대조하는 것은 그대로다(1단계의 제외 목록에서 `approval` `love` `neutral` `annex` `colonize` `novichok` `fight` `treaty` `becomeregion` 을 뺀다).

## 오류 처리

| 상황 | 동작 |
|---|---|
| 주소 찾기 실패 | 글쇠 방식(1단계와 같다). 로그에 어느 조건이 깨졌는지 한 줄 |
| 주소는 찾았는데 일관성이 깨짐 | 위와 같다. 로그에 한 번만 |
| 게임 밖 · 멀티플레이 | 단추가 꺼진다. 대기열의 명령은 버린다 |
| 직접 실행 중 예외 | 오류 가드(위). 게임은 죽지 않지만 상태가 어긋났을 수 있다 — 창에 경고를 띄우고 그 뒤로 아무것도 실행하지 않는다 |
| 이름표에 없는 번호 | `#<번호>` |
| `SRTOYBOX_DIRECT=0` | 주소를 찾아도 명령은 글쇠 방식으로 넣는다(상태 읽기와 단추 끄기는 그대로). 문제가 생겼을 때의 탈출구이자 회귀 확인용 |

로그(`toybox.log`)에 더하는 줄: `게임 상태를 읽습니다 (직접 실행)` / `게임 상태를 읽을 수 없습니다 (<까닭>) — 글쇠 방식` / `직접 실행: <명령>` / `직접 실행 중 예외 0x… (<명령>)`.

## 테스트와 검증

**자동 테스트** (게임 없이. 설치된 게임 파일이 있어야 하는 것은 없으면 건너뛴다)

- 주소 찾기: 설치된 `SupremeRuler2030.exe` 를 RVA 대로 펼쳐 넘기면 위 표의 주소가 나온다(파일의 TimeDateStamp 가 `0x695377b6` 일 때만 값을 대조하고,
  다른 빌드면 "찾았다 / 못 찾았다"만 적는다). 작은 가짜 이미지로 실패 조건을 하나씩: 닻 문자열 2개, `call` 2곳, 머리의 명령 없음, 두 치트의 포인터가 다름, 주소가 이미지 밖.
- 상태 읽기: 가짜 메모리(전역 자리와 지역 객체 몇 개)를 만들어 — 게임 안 / 메뉴(포인터 NULL) / 낡은 포인터(읽을 수 없는 주소) / 일관성이 깨진 경우(표[인덱스] != 포인터, 번호 0) / 멀티플레이 / 지역 목록(`+0` 이 0 인 것은 빠진다).
- 이름표: 번역 테이블에서 만든 표에 1499 = 독일 · Germany 가 있고, 없는 번호는 `#번호`.
- 명령: 대상별 문자열(`cheat approval 1499`, `cheat love 1106`, `cheat treaty`), 대상이 없으면 만들지 않는다.
- 직접 실행(가짜 게임): 테스트가 주소 묶음을 넣어 준다 — 명령 처리 함수 자리에 기록하는 가짜 함수, 전역 자리에 가짜 메모리.
  이를 위해 `exports` 에 주소 묶음을 바꿔 넣는 함수를 하나 둔다(테스트만 부른다. 1단계의 `srtoybox_simulate` 처럼 테스트와 훅이 쓰는 C 인터페이스의 일부다).
  단추를 누르면 가짜 함수가 `cheat allowcheats` 다음에 명령을 받는다(비트가 서 있으면 명령만) / 게임 밖이면 불리지 않고 단추가 꺼져 있다 /
  가짜 함수가 잘못된 주소에 쓰면 가드가 잡고 그 뒤로 아무것도 실행하지 않는다 / `SRTOYBOX_DIRECT=0` 이면 가짜 함수가 불리지 않고 글쇠가 간다.
- 2바이트 글자 합치기: 앞 · 뒤 바이트 → 한 글자, 앞 바이트 뒤에 엉뚱한 것이 오면 버린다.
- 1단계의 테스트는 그대로 통과해야 한다(주소를 못 찾는 프로세스에서는 1단계와 같은 동작).

**게임 안 확인** (화면 밖 게임. 저장하지 않는다)

| # | 한 것 | 볼 것 |
|---|---|---|
| H1 | 메인 메뉴에서 창을 연다 | 상태 줄 "게임을 진행 중이 아닙니다", 단추가 꺼져 있다. 눌러도 게임에 아무것도 가지 않는다 |
| H2 | 게임에 들어간다 | 상태 줄 "플레이 중: 독일 (1499)" |
| H3 | "국고 +$10 B" | 국고 +$10 B. **게임의 설정 창이 뜨지 않는다.** 로그에 `직접 실행` |
| H4 | "내 나라 지지율 100%" | 지지율 100% |
| H5 | 폴란드를 골라 "관계 최고" → "관계 중립" | 외교 화면의 관계 막대 |
| H6 | 나라 하나씩: 병합 / 식민지화 / 지도자 제거 | 07 에서 본 효과. 한 번 더 누르기가 듣는다 |
| H7 | 지도에서 나라를 고르고 "동맹 맺기", "전쟁 붙이기" | 07 에서 본 효과 |
| H8 | "이 나라로 플레이" | 상태 줄이 그 나라로 바뀌고, 목록에서 그 나라가 빠지고 독일이 들어온다 |

| H10 | 게임 메뉴로 메인 메뉴에 나온다 | 상태 줄이 "진행 중이 아닙니다"로, 단추가 꺼진다. 다시 들어가면 켜진다 |

1단계에서 미뤄 둔 "넣는 동안 게임이 앞 창일 때"는 직접 실행에서는 없는 문제다(글쇠를 넣지 않는다). 글쇠 방식에서는 그대로 남는다.

## 설치와 제거

1단계와 같다(`srkit toybox-build` → `srkit deploy toybox --apply`). ToyBox 는 사용자의 요청으로 설치되어 있다(2026-10-06).
개발 중에는 시험용 빌드로 바꿔 넣고(갱신: `srtoybox.dll` 한 개 — 미리보기에 그 밖의 줄이 있으면 멈춘다), 끝나면 최종 빌드가 설치된 상태로 둔다.
한글화 훅(`WTSAPI32.dll`)은 고치지 않는다.

## 공개 저장소 제약

- 실행 파일의 바이트나 디스어셈블리 덤프를 저장소에 넣지 않는다. 문서와 코드에 들어가는 것은 주소(빌드 번호와 함께), 찾는 절차, 짧은 바이트 서명뿐이다.
- 분석에 쓴 스크립트와 산출물은 저장소 밖(스크래치)에 있다.

| 가드가 예외를 잡은 뒤 게임 상태가 어긋난다 | 창의 경고(저장하지 말 것)와 그 뒤 실행 중지 |
| 직접 호출이 게임의 화면 갱신 · 알림을 빠뜨린다 | H3 ~ H8 에서 효과를 화면으로 확인한다. 빠지면 그 치트는 글쇠 방식으로만 실행하게 표에 표시한다 |
| 목록에 없는 지역 번호로 치트를 넣는다 | 목록은 메모리에서 읽은 "이번 게임의 지역"뿐이다. 게임의 함수도 없는 번호는 무시한다 [확인: 정적] |
| 되돌릴 수 없는 치트를 잘못 누른다 | 한 번 더 누르기, 고른 나라를 창에 늘 보여 준다 |
| 치트 허용이 켜지면 그 판의 업적이 주어지지 않을 수 있다 | 문서에 적는다(1단계와 같다. 손으로 넣어도 같다) |

## 완료 기준

1. 자동 테스트가 통과한다(1단계의 것 포함).
2. H1 ~ H12 를 보고 결과를 `docs/10` 의 "확인한 것"에 [확인] / 보지 못한 것으로 나눠 적는다.
3. 게임 폴더에는 최종 빌드의 `srtoybox.dll` 이 설치되어 있고, 기록해 둔 다른 파일의 해시 10개가 그대로다.
4. `uv run srkit locate` 가 이 빌드에서 위 표의 주소를 보고한다.
5. `docs/10` · `docs/11` · `docs/07` · `docs/09` 가 이 단계의 사실을 담는다.
## 보완 내역 (2026-10-07, 구현 계획을 쓰며)

- **지역 수의 주소도 찾는다.** 주소 찾기 표에 지역 수가 빠져 있었다. `becomeregion` 블록의
  `44 8B 0D d32 45 33 F6 45 85 C9 0F 88 d32 48 8D 0D d32` 에서 지역 수와 지역 표를 함께 얻고, 지역 표가 `populate` 에서 얻은 것과
  같은지를 대조에 더했다(대조는 여덟 가지가 됐다).
- **나라 이름표는 상태 읽기와 함께 만들었다**(작업 순서의 2번). 상태 줄이 플레이어의 이름을 보여야 해서다.
- **지역 목록은 창이 "외교·영토" 탭을 보이는 동안 1초마다 읽는다**(프레임마다가 아니다).
- **직접 실행 뒤 열려 있던 패널은 스스로 다시 그려지지 않는다**(일시 정지 중). 위험 표의 "직접 호출이 게임의 화면 갱신을 빠뜨린다"가
  실제로 그랬다. 값은 바뀌므로 직접 실행을 그대로 두고, 창에 안내 한 줄을 두었다("일시 정지 중에는 게임 화면의 숫자가 그 패널을 누르거나
  다시 열 때 바뀝니다"). 게임이 자기 호출 뒤에 부르는 함수는 무엇인지 몰라 부르지 않는다.
- **나라 이름표는 번역 표 둘에서 만든다**(`localtext-regions.csv` 와 `.extra.csv`). 한 파일만으로는 여섯 지역의 이름이 빠졌다.
- **나라 목록에는 지역의 상태가 2(사람) 또는 3(AI)인 것만 올린다.** 지역 표에는 이번 판에 없는 지역(상태 5 — 서독 · 소련 · 네브래스카 등 128개)도
  들어 있어, 그대로 두면 없는 지역에 "이 나라로 플레이"를 넣을 수 있었다. 값의 뜻은 2030 - 세계의 한 판에서 본 분포로 정한 것이다 [추정].
- 로그의 줄은 `게임 상태를 읽습니다 (명령 처리 함수 +0x…)` 로 했다(찾은 함수의 자리가 남는다).
