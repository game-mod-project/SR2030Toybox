## 목적

2단계의 ToyBox 는 게임의 내장 치트를 대신 넣어 줄 뿐이다. 내장 치트는 "모든 물자에 한꺼번에 더하기"밖에 없어, 물자 하나만 고치거나
값을 깎거나 0 으로 만들거나 일정 수준으로 유지할 수 없다. 3단계는 ToyBox 가 **게임의 메모리에 값을 직접 쓴다.**

사용자가 2단계를 써 보고 낸 요구(2026-10-09):

> 모드 기능중 연구빼고는 정상 동작함 - 연구는 지식값은 오르나 실제 일부 연구(군사 연구등)가 완성이 되지는 않아 보임.
> 돈/물자/연구/부대는 세부 기능을 상세 분류 할 필요 있음

요구는 앞 단계와 같다(사용자, 2026-10-06): 모든 기능은 게임 안의 설정 창에서, 적용은 플레이어가 지금 플레이 중인 국가에만.

## 3단계의 나눔 (2026-10-09, 사용자)

요구가 한 설계에 담기에는 커서 네 묶음으로 나눴다. 묶음마다 설계 → 계획 → 구현을 따로 돈다. **이 문서는 A 다.**

| 묶음 | 사용자의 요구 | 순서 |
|---|---|---|
| **A. 돈 · 물자 값** | 국고 −/0/+, 국고 최소 유지 금액, 물자별 재고 −/0/+, 물자별 최소 유지량 | 첫째(이 문서) |
| B. 연구 | 일부 연구가 완료되지 않는 원인, 개별 연구 미/완료 여부 체크 | A 다음(B 와 C 의 순서는 그때 정한다) |
| C. 부대 | 분류별 부대 목록에서 골라 고른 칸에 생성, 부대의 보급 · 경험 수정, 국가 군대 전체/선택 보급 | 〃 |
| D. 배율 | 국고 세금/지출 배율, 국방비 지출 배율, 물자별 생산 · 소비 배율, 연구 속도 배율 | 마지막 |

A 를 먼저 하는 까닭: A 에서 만드는 "값 쓰기 + 유지" 계층을 B · C · D 가 다시 쓰고, 국고의 자리는 이미 안다.
D 를 마지막에 두는 까닭: 게임이 매일 계산하는 자리를 찾아야 하고 방법도 정해지지 않았다.

## 설계 전에 확인한 것

조사는 정적 분석 하나다: 설치된 실행 파일을 읽어 `cheat treasury` · `cheat georgew` · `cheat products` · `cheat branson` 을 처리하는 명령을
디스어셈블해 봤다(Python + capstone). 게임은 띄우지 않았고 게임 폴더에는 쓰지 않았다. 분석에 쓴 스크립트는 저장소 밖에 있다.

### 국고 [확인: 정적]

- `cheat treasury N`(`0x522b7b` 부터): `N` 을 `strtol` 로 읽어(부호 검사 없음) float 상수를 곱하고 double 로 바꿔
  `[플레이어 포인터 + 0x14B88]` 에 더한다 — `F2 0F 58 80 88 4B 01 00`(더하기), `F2 0F 11 80 88 4B 01 00`(쓰기). 그 밖에 하는 일이 없다(다른 함수를 부르지 않는다).
- `cheat georgew`(`0x523ef9` 부터): 같은 칸에 상수를 더한다.
- 플레이어 포인터는 2단계가 이미 찾는 전역(`0x18295f8`)이다.

### 물자 재고 [확인: 정적]

- `cheat products N`(`0x522be9` 부터): **`N` 이 0 이하면 아무것도 하지 않는다**(`comiss` → `jbe`). 내장 치트로는 재고를 깎을 수 없다.
- 칸이 **12개**다(`i` = 0 … 11). 칸마다 같은 일을 한다:
  1. 세계 자료 객체(전역 포인터 `0x1af5868`)의 `[+0x18 + 0x84·i]`(float)가 0 보다 클 때만 —
  2. 지역 표[플레이어 인덱스] 객체의 `[+0x14DA4 + 0x150·i]`(float)에 더한다 — `F3 0F 58 81 off32`(더하기), `F3 0F 11 81 off32`(쓰기).
     마지막 칸만 레지스터가 달라 `F3 0F 58 89 off32` · `F3 0F 11 89 off32` 다.
- `cheat branson` · `cheat bezos`(`0x524da2` 부터): 같은 칸, 같은 검사, 더하는 값만 상수다.
- 게임의 물자 이름 목록은 11개다: 번역 표 `variables.csv` 의 `LOCALIZE|productsl|0` ~ `|10` — 농산물, 고무, 목재, 석유, 석탄, 금속 광석, 우라늄, 전력,
  소비재, 산업재, 군수품. 같은 목록의 11번은 "전체"(All)다 [확인: 파일].

| 무엇 | 자리 | 형 | 근거 |
|---|---|---|---|
| 국고(달러) | 지역 객체 `+0x14B88` | double | [확인: 정적] 쓰는 명령 · [확인: 실행] 14.43 B(2단계) |
| 물자 `i` 의 재고 | 지역 객체 `+0x14DA4 + 0x150·i`, `i` = 0 … 11 | float | [확인: 정적] 쓰는 명령 12개 |
| 세계 자료 객체의 포인터 | RVA `0x1af5868` | qword | [확인: 정적] |
| 물자 `i` 를 쓰는가 | 세계 자료 객체 `+0x18 + 0x84·i` | float. 0 보다 크면 쓴다 | [확인: 정적] 검사. 값의 뜻은 모른다 |

플레이어의 지역 객체에 닿는 길은 둘이다(포인터 전역 / 지역 표[인덱스]). 2단계의 일관성 검사가 둘이 같은 객체임을 읽을 때마다 본다.

### 아직 보지 않은 것

1. ToyBox 가 그 칸에 직접 쓴 값을 게임이 그대로 쓰는지(화면, 다음 날의 계산). 게임의 치트가 하는 일이 그 쓰기뿐이므로 될 것으로 본다 [추정] — **이 설계의 전제다.**
2. 칸 번호와 물자 이름의 대응. 게임의 이름 목록 순서대로(0 = 농산물 … 10 = 군수품)일 것으로 본다 [추정].
3. 12번째 칸(`i` = 11)이 무엇이고 이 게임에서 쓰이는지. 이름 목록에 짝이 없다 — 쓰지 않는 칸일 것으로 본다 [추정].
4. 국고가 음수일 때의 게임(07 에서 `trumpme` 로 −$1 T 가 된 것은 봤다), 재고가 0 일 때의 게임.
5. 날짜를 넘기는 계산이 다른 스레드에서 돌 때 ToyBox 의 쓰기와 겹치는지(2단계에서도 보지 못했다 — [docs/11](../../11-game-internals.md)).
6. DLC 의 판(1936 · 대전쟁 등)에서 물자 구성이 같은지.
7. 다른 빌드에서 자리 찾기가 되는지(이 빌드 하나만 있다).

## 범위

**넣는 것**

1. 값의 자리 찾기: 국고 칸, 재고 칸(첫 자리 · 간격 · 개수), "쓰는 물자" 표. 자리를 코드에 적지 않는다.
2. 값 읽기와 쓰기: 플레이어 지역 객체의 국고 1칸과 재고 12칸.
3. 돈 탭: 현재 국고, 입력란 + 더하기 · 빼기 · 이 값으로, 빠른 단추 다섯, 최소 유지.
4. 물자 탭: 물자마다 현재 재고, −1억 · −100만 · 0 · +100만 · +1억, 최소 유지. "모든 물자" 줄.
5. 최소 유지: 0.5초마다 검사, 설정 저장, 상태 줄의 "유지 중".
6. 자리를 못 찾을 때의 자동 전환(지금의 단추 여섯 개), 탈출구 `SRTOYBOX_WRITE=0`.
7. `uv run srkit locate` 에 새 자리 출력.
8. 문서.

**넣지 않는 것**

- 연구, 부대, 배율(묶음 B · C · D).
- GDP 와 장비 수치(내장 치트가 없는 값 — [docs/09](../../09-cheat-mod-plan.md)의 로드맵).
- 플레이어가 아닌 지역의 값.
- 치트 허용 비트를 켜는 것(결정 사항). 값 쓰기만 쓴 판은 게임이 치트를 쓴 판으로 보지 않는다.
- 직접 쓴 뒤 열려 있던 게임 패널을 다시 그리게 하는 것(2단계의 한계 그대로 — 패널을 누르거나 다시 열면 따라온다).
- 멀티플레이.

## 구성

```
srtoybox.dll
  locate    ── (더함) 값의 자리 찾기 — 순수 함수
  game      ── (더함) 국고 · 재고 읽기와 쓰기
  values    ── (새로) 지금 값 + 요청 → 쓸 값 — 순수 함수
  keeper    ── (새로) 값 쓰기 요청의 대기열, 0.5초마다의 유지 검사
  products  ── (새로) 칸 번호 → 물자 이름 (빌드할 때 번역 표에서 만든 표)
  settings  ── (더함) 유지의 켜짐과 값
  ui        ── (더함) 돈 · 물자 탭, 상태 줄의 "유지 중"
```

### 값의 자리 찾기 (`locate`)

2단계의 주소 묶음과 **따로** 판정하는 둘째 묶음이다. 2단계의 주소를 찾았을 때만 찾는다.

치트의 **구간**: 그 치트의 문자열을 쓰는 자리(`lea r,[rip+d]`)부터, 그 뒤에 처음 나오는 다른 치트 문자열(`"cheat …"`)을 쓰는 자리 앞까지.
0x400 바이트를 넘지 않는다. (`branson` 과 `bezos` 는 본문을 함께 쓰므로 뒤쪽인 `bezos` 의 구간을 본다.)

| 찾을 것 | 절차 |
|---|---|
| 국고 칸 | `"cheat treasury"` 의 구간에 있는 `F2 0F 58 80 off32` 의 `off32` |
| 재고 칸 | `"cheat products"` 의 구간에 있는 `F3 0F 11 (81\|89) off32` 를 차례로 모은 `off32` 들 — 첫 자리, 간격, 개수 |
| 세계 자료 포인터 | 같은 구간의 첫 `48 8B 05 d32` |
| "쓰는 물자" 표 | 같은 구간의 `F3 0F 10 40 d8`(첫 칸)과 `F3 0F 10 80 off32`(나머지) — 첫 자리, 간격 |

"찾았다"의 조건(하나라도 어긋나면 값 쓰기를 끈다):

1. `treasury` 의 국고 칸이 구간에 1곳이고, 2단계가 `georgew` 에서 읽는 `off32`(지금은 대조에만 쓰는 값)와 같다.
2. 재고에 쓰는 명령이 정확히 12개이고, 자리가 같은 간격으로 늘어난다(간격은 4 의 배수이고 0 보다 크다).
3. `"cheat bezos"` 의 구간에 있는 첫 `F3 0F 11 81 off32` 가 2 의 첫 자리와 같다.
4. 그 구간의 `48 8B 05 d32` 가 모두 같은 주소를 가리킨다.
5. "쓰는 물자" 검사가 정확히 12개이고 같은 간격으로 늘어난다.
6. 자리가 모두 0 보다 크고 `0x100000` 보다 작으며, 국고 칸(8바이트)과 재고 칸들(4바이트씩)이 겹치지 않는다.
7. 세계 자료 포인터의 주소가 이미지 안에 있다.

값의 자리만 못 찾으면 2단계의 기능(상태 읽기, 직접 실행, 나라 고르기)은 그대로 동작한다.

### 값 읽기와 쓰기 (`game`)

- **읽기**: 국고(double), 칸마다 "쓰는가"와 재고(float). 2단계의 안전한 읽기(자기 프로세스에 대한 `ReadProcessMemory`)로 읽는다. `in_game` 일 때만 뜻이 있다.
- **쓰기**: 국고 한 칸, 또는 재고 한 칸. 자기 프로세스에 대한 `WriteProcessMemory` 로 쓴다 — 낡은 포인터를 만나도 죽지 않고 실패로 돌아온다.
  쓴 뒤 다시 읽어 쓴 값과 같은지 본다.
- **쓰기 직전에 매번 다시 확인한다**(하나라도 아니면 쓰지 않는다): 값의 자리를 찾았다 / `in_game` 이다(2단계의 일관성 포함) / 멀티플레이가 아니다 /
  오류 가드가 걸리지 않았다 / (재고) 그 칸이 쓰는 물자다 / 쓸 값이 유한한 수다.
- 쓰는 곳은 **플레이어 지역 객체의 국고 1칸과 재고 12칸뿐**이다. 다른 지역, 다른 칸, 전역에는 쓰지 않는다.
- `game.h` 머리말의 "읽기만 한다 — 게임의 메모리에 쓰지 않는다"는 "쓰는 곳은 이 둘뿐이다"로 고친다.

### 값 계산 (`values`)

창도 게임도 모르는 순수 함수다: (지금 값, 요청) → 쓸 값 또는 "쓰지 않는다".

| 요청 | 국고 | 재고 |
|---|---|---|
| 더하기 · 빼기 | 지금 값 ± 금액 | 지금 값 ± 수량. **0 아래로 내려가지 않는다** |
| 맞추기 | 그 값 | 그 값(0 이상) |
| 바닥(유지) | 지금 값이 설정보다 작으면 설정, 아니면 쓰지 않는다 | 같다 |

- 국고는 음수가 될 수 있다(게임이 허용한다). 결과는 ±$1,000 T 안으로 자른다.
- 재고의 결과는 0 이상 10억 이하로 자른다.
- 지금 값이 NaN 이나 무한대면 쓰지 않는다(구조가 바뀐 것일 수 있다).
- 계산은 double 로 하고 재고는 쓸 때 float 로 바꾼다.

### 요청의 대기열과 유지 (`keeper`)

- 단추를 누르면 요청(대상 · 종류 · 값)이 대기열에 들어간다. "모든 물자" 줄의 요청은 쓰는 물자마다의 요청으로 풀린다.
- 창 스레드의 타이머(2단계의 직접 실행과 같은 자리)가 대기열을 비운다. 게임의 함수를 부르는 도중에는 쓰지 않는다(2단계의 겹침 방지를 함께 쓴다).
- **유지 검사**는 0.5초마다, ToyBox 창이 닫혀 있어도 돈다. 켜진 항목마다 바닥 요청을 낸다.
  게임 밖 · 멀티플레이 · 오류 가드 뒤에는 쉰다. 플레이하는 나라가 바뀌면(`becomeregion`) 그 뒤로는 새 나라의 값을 본다 — 앞의 나라는 건드리지 않는다.
- 게임 밖에서 대기열에 남은 요청은 버리고 창에 알린다(2단계와 같다).

### 물자 이름 (`products`)

`srkit toybox-build` 가 `mods/korean/translation/variables.csv` 의 `LOCALIZE|productsl|0` ~ `|10` 에서 `칸, 한글 이름, 영문 이름` 표를 만들어 DLL 에 넣는다
(나라 이름표와 같은 방식 — 생성물은 저장소에 넣지 않는다). 표에 없는 칸은 `물자 #12` 처럼 보인다.
칸과 이름의 대응은 게임에서 확인한 뒤에 확정한다("아직 보지 않은 것"의 2 · 3).

### 설정 (`settings`)

`toybox.ini` 에 더하는 줄(형식은 지금과 같은 `키=값`. 모르는 줄은 버리고 틀린 값은 기본값):

| 키 | 값 | 기본 |
|---|---|---|
| `money.amount` | 돈 탭 입력란(백만 달러). 1 ~ 1,000,000 | 10000 |
| `keep.treasury` | 0 / 1 | 0 |
| `keep.treasury.value` | 유지할 국고(백만 달러). 0 ~ 1,000,000 | 0 |
| `keep.stock.<칸>` | 0 / 1 (`<칸>` = 0 … 11) | 0 |
| `keep.stock.<칸>.value` | 유지할 수량. 0 ~ 1,000,000,000 | 0 |

지금의 `treasury=` · `products=` 값은 예전 단추가 계속 쓴다.

### 창 (`ui`)

**상태 줄**(창 맨 위, 탭의 내용을 내려도 남는다) — 유지가 켜진 것이 있으면 뒤에 붙는다:

- `플레이 중: 독일 (1499) · 유지 중: 국고, 석유, 전력` (넷을 넘으면 `국고 외 5개`)
- `게임을 진행 중이 아닙니다 — 단추가 꺼져 있습니다 · 유지 3개 켜짐(게임에 들어가면 적용)`

**돈 탭**

```
국고: $ 14.43 B

[ 10000 ] 백만 달러   [더하기] [빼기] [이 값으로]

[−$100 B] [−$10 B] [ 0 ] [+$10 B] [+$100 B]

[x] 최소 유지  [ 50000 ] 백만 달러
```

**물자 탭** — 이번 판에서 쓰는 물자만 줄로 나온다. 창이 좁으면 표가 가로로 구른다. 창의 첫 크기를 500×460 에서 720×520 으로 넓힌다
(이미 창을 써 본 사용자의 저장된 크기는 그대로다).

```
물자       재고     빼기 / 더하기                           최소 유지
모든 물자     –     [−1억][−100만][ 0 ][+100만][+1억]
농산물     129 K    [−1억][−100만][ 0 ][+100만][+1억]   [x] [ 500000 ]
고무        12 K    [−1억][−100만][ 0 ][+100만][+1억]   [ ] [      0 ]
 …
```

- "모든 물자" 줄은 쓰는 물자 모두에 같은 일을 한다. 이 줄에는 재고 표시와 최소 유지가 없다.
- 국고와 재고의 숫자는 탭이 보이는 동안 프레임마다 읽는다. 게임과 같은 줄임 표기(K · M · B · T)로 보인다.
- 단추가 꺼지는 조건은 2단계와 같다(게임 밖, 멀티플레이, 오류 가드 뒤).
- 한 번 더 누르기는 두지 않는다 — 0 으로 만들기와 빼기는 다시 더해 되돌릴 수 있다.
- 창 바닥의 안내("값은 바로 바뀝니다. 게임 화면의 숫자는 그 패널을 누르거나 다시 열 때 따라옵니다.")는 그대로 맞는 말이다.

**예전 단추와의 관계**

- 값 쓰기를 쓸 수 있을 때 돈 · 물자 탭은 위의 화면이다. 지금의 단추 여섯(국고 추가 · +$10 B · +$100 B, 모든 물자 추가 · +100만 · +1억)은 그리지 않는다.
- 값 쓰기를 쓸 수 없을 때(자리를 못 찾았다 / `SRTOYBOX_WRITE=0` / 게임 상태를 읽지 못해 글쇠 방식이다) 두 탭은 지금의 단추 여섯 그대로다.
- 기능 표(`features`)의 여섯 줄은 남긴다 — 자동 테스트가 07 과 대조하는 것도 그대로다.

### 로그

`toybox.log` 에 더하는 줄:

| 줄 | 뜻 |
|---|---|
| `값을 씁니다 (국고 +0x…, 재고 +0x… 간격 0x… × 12)` | 값의 자리를 찾았다 |
| `값을 쓸 수 없습니다 (<까닭>) — 예전 단추` | 자리를 찾지 못했다. 2단계의 기능은 그대로다 |
| `값을 쓰지 않습니다 (SRTOYBOX_WRITE=0)` | 그 환경 변수를 준 채 띄웠다 |
| `값 쓰기: 국고 14.43 B → 24.43 B` · `값 쓰기: 석유 1.10 M → 2.10 M` | 단추로 쓴 것 |
| `유지 켬: 석유 1000000` · `유지 끔: 석유` | 창에서 켜고 끈 것 |
| `유지: 석유 812 K → 1.00 M` | 유지가 값을 올렸다. 항목마다 **이번 실행의 첫 번째만** 적는다(0.5초마다 적지 않는다) |
| `값 쓰기 실패 (<대상>) — 값 쓰기를 끕니다` | 아래 "오류 처리" |

## 오류 처리

| 상황 | 동작 |
|---|---|
| 값의 자리를 찾지 못함 | 값 쓰기를 끈다. 돈 · 물자 탭은 예전 단추. 로그에 어느 조건이 깨졌는지 한 줄. 2단계의 기능은 그대로 |
| 게임 밖 · 멀티플레이 | 단추가 꺼진다. 대기열의 요청은 버린다. 유지는 쉰다 |
| 지금 값이 NaN · 무한대 | 쓰지 않는다. 창에 알림 |
| 쓰기가 실패하거나 다시 읽은 값이 다르다 | 이번 실행에서 값 쓰기와 유지를 끄고 창에 알린다(예전 단추가 나온다). 로그에 한 줄 |
| 직접 실행의 오류 가드가 걸린 뒤 | 값 쓰기와 유지도 멈춘다 |
| `SRTOYBOX_WRITE=0` | 값 쓰기를 끈다(자리는 찾아 로그에 적는다). 탈출구이자 회귀 확인용 |
| `SRTOYBOX_READ=0` | 게임을 읽지 않으므로 값 쓰기도 없다 |

**승인된 설계안과 다른 점 하나.** 대화에서는 "쓰다가 예외가 나면 직접 실행 오류와 같이 처리한다(빨간 경고, 이후 중단)"고 했다. 문서로 옮기며
쓰기를 `WriteProcessMemory` 로 정해 예외가 나지 않게 했다 — 실패하면 쓴 것이 없으므로 "저장하지 말라"는 빨간 경고 대신 값 쓰기만 끄고 알린다.

## 테스트와 검증

**자동 테스트** (게임 없이. 설치된 게임 파일이 있어야 하는 것은 없으면 건너뛴다)

- 자리 찾기: 설치된 실행 파일에서 국고 `0x14B88`, 재고 `0x14DA4` · 간격 `0x150` · 12칸, "쓰는 물자" `0x18` · 간격 `0x84`
  (TimeDateStamp 가 `0x695377b6` 일 때만 값을 대조). 가짜 이미지로 실패 조건을 하나씩: 쓰는 명령이 11개, 간격이 고르지 않다, `branson` 의 첫 자리가 다르다,
  국고 칸이 `georgew` 와 다르다, 자리가 겹친다. 값의 자리만 없는 이미지에서 2단계의 주소는 그대로 찾는다.
- 값 계산: 더하기 · 빼기 · 맞추기 · 바닥, 재고가 0 에서 멈춘다, 국고는 음수가 된다, 상한, NaN · 무한대.
- 읽기와 쓰기(가짜 게임 메모리): 게임 안에서는 그 칸만 바뀐다(둘레의 바이트는 그대로) / 메뉴 · 멀티플레이 · 일관성이 깨진 상태 · 쓰지 않는 물자 칸에는 쓰지 않는다 /
  읽을 수 없는 포인터에서는 실패로 돌아온다.
- 대기열과 유지: 요청의 순서, "모든 물자"가 쓰는 칸마다로 풀린다, 유지는 0.5초에 한 번 · 값이 아래일 때만 쓴다, 나라가 바뀌면 새 객체에만 쓴다,
  게임의 함수를 부르는 도중에는 쓰지 않는다, 쓰기가 실패하면 그 뒤로 쓰지 않는다.
- 설정: 새 키의 왕복, 범위 밖 · 깨진 값은 기본값, 예전 설정 파일을 그대로 읽는다.
- 창(그린 것의 목록): 돈 · 물자 탭의 항목과 숫자, 쓰지 않는 물자는 줄이 없다, 상태 줄의 "유지 중", 값 쓰기를 쓸 수 없을 때 예전 단추가 나온다,
  메뉴에서는 단추가 꺼진다.
- 물자 이름표: 번역 표에서 만든 표에 3 = 석유 · Petroleum 이 있고, 없는 칸은 `물자 #번호`.
- 2단계까지의 테스트는 그대로 통과해야 한다.

**게임 안 확인** (화면 밖 게임, 백그라운드. 저장하지 않는다. 한 판에서 시간은 3일 넘게 흘리지 않는다 — 게임이 7일마다 자동 저장한다)

저장되어 사용자의 판에 적용되면 안 된다.

## 설치와 제거

2단계와 같다(`srkit toybox-build` → `srkit deploy toybox --apply`). ToyBox 는 사용자의 요청으로 설치되어 있다(2026-10-06).
**개발 중에는 시험용 빌드로 바꿔 넣고**(갱신: `srtoybox.dll` 한 개 — 미리보기에 그 밖의 줄이 있으면 멈춘다), 끝나면 최종 빌드가 설치된 상태로 둔다.
이 문서의 승인은 그 바꿔 넣기의 승인을 포함한다. 한글화 훅(`WTSAPI32.dll`)은 고치지 않는다.

## 공개 저장소 제약

- 실행 파일의 바이트나 디스어셈블리 덤프를 저장소에 넣지 않는다. 문서와 코드에 들어가는 것은 자리(빌드 번호와 함께), 찾는 절차, 짧은 바이트 서명뿐이다.
- 분석에 쓴 스크립트와 산출물은 저장소 밖(스크래치)에 있다.
