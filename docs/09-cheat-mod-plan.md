# Supreme Ruler 2030 치트/모드 제작 계획

조사 기준: Steam appid `2093410`, build `21347933`(게임 12.1.1360), 2026-10-06. 목적: **내 싱글플레이에서 쓸 치트 수단.**
근거 문서: [05 게임 구조](05-game-systems.md) · [06 데이터 참조](06-data-reference.md) · [07 내장 치트](07-cheats.md) · [08 Workshop 조사](08-workshop-survey.md)

표기: **[확인]** 파일·실행 파일·게임 안에서 직접 확인, **[추정]** 정황으로 판단, **[위키]** 공식 위키에 있으나 이 빌드에서 미확인.

## 결론

- **(2026-10-06 방향 수정) 만드는 것은 게임 안 모드 설정 창 "ToyBox" 다.** 사용자가 요구를 둘 정했다 — 모든 기능을 게임 안의 창에서 설정하고,
  설정은 플레이어가 플레이 중인 국가에만 적용한다. 아래의 시나리오 모드는 이 요구를 채우지 못해 뒷단계의 후보로 내려갔다.
  1단계(창 + 플레이어 대상 내장 치트 16개)는 만들었다 — [10 ToyBox](10-toybox.md).
- **원안의 예시 아홉 개 가운데 일곱 개는 게임에 든 내장 치트로 끝난다.** 돈, 자원, 연구, 국가 관계, 군사력, 장비 생산, 인구 — 모두 게임에서 넣어 확인했다.
- **내장 치트가 없는 것은 GDP 와 부대 스탯(장비의 수치) 둘이다.** 둘 다 시나리오 파일 끝에 블록을 덧붙이는 방법으로 바뀌는 것을 게임에서 확인했다 — 장비 쪽은 **비용 열 하나**로 확인했고, 공격·방어·생산 일수 같은 다른 열은 같은 방식이라 될 것으로 본다 [추정]. 캐시를 다시 만들 필요가 없어 넣고 빼기가 깨끗하다. 처음에는 이 방법을 쓰는 시나리오 모드 하나를 만들 계획이었다(위의 방향 수정으로 뒷단계의 후보가 됐다).
- **Workshop 에는 내 쪽만 유리하게 하는 데이터 모드가 없다.** 있는 것은 게임 밖 프로그램 둘(메모리 트레이너, 세이브 편집기)과, 모든 나라에 똑같이 적용되는 균형 조정뿐이다.
- **원본 데이터(`DEFAULT.UNIT`, `*.CVP`)를 직접 고치는 모드는 만들지 않는다.** 캐시를 다시 만들어야 하고, 그때 게임이 설치 폴더의 캐시 파일을 고쳐 쓴다.
- **게임이 업데이트되어 치트가 사라져도 버틸 수 있게 준비했다.** 감지 명령(`srkit cheats-check`)을 두었고, 치트 없이 같은 결과를 내는 길을 예시마다 적었다 — 아래 "게임 업데이트 대비".

## 수단 여섯 가지

| 수단 | 적용 시점 | 대상 | Workshop 배포 | 캐시 재생성 | 검증 |
|---|---|---|---|---|---|
| 내장 치트 (`cheat …`) | 진행 중 | 대부분 플레이어 | 필요 없다(게임에 들어 있다) | 무관 | [확인] 89개를 넣어 효과 45개 — [07](07-cheats.md) |
| 시나리오 설정 — 로비의 게임 옵션, 진행 중의 게임 설정 창 | 새 게임 / 진행 중 | 옵션마다 다르다 | 필요 없다 | 무관 | [확인] 옵션이 있는 것. 초기 자금은 효과까지 확인 |
| 시나리오 설정 — 시나리오 파일의 `&&GMC` | 새 게임 | 그 시나리오 | 가능 | **필요 없다** [확인] | [확인] `initialfunds` |
| 시나리오 설정 — 시나리오 파일 끝에 덧붙이는 `&&CVP` · `&&UNITS` | 새 게임 | 지정한 지역 · 장비 | 가능 | **필요 없다** [확인] | [확인] `gdpc`, `treasury`, 장비 비용 |
| 데이터 표 (`Maps\*.CVP`, `Maps\DATA\DEFAULT.*`) | 새 게임 | 모든 지역 또는 지정한 지역 | 가능(캐시를 함께 실어야 한다) | **필요하다** [확인]. 게임이 `Cache\` 의 파일을 고쳐 쓴다 | [확인] 장비 비용, `gdpc` |
| 실행 중 훅 (한글화의 훅 DLL 확장) | 진행 중 | 플레이어 | 불가(DLL 은 Workshop 으로 못 보낸다 — [02](02-modding-system.md)) | 무관 | [확인] 창을 그리고 내장 치트를 넣는 것까지 — [10](10-toybox.md) |
| 세이브 편집 | 진행 중 | 모든 지역 | 불가 | 무관 | [추정] 조사하지 않았다. Workshop 에 편집기가 있다 |
| Workshop 기존 모드 | 항목마다 다르다 | 대부분 모든 지역 | – | 항목마다 다르다 | 설명만 읽었다 — [08](08-workshop-survey.md) |

"시나리오 설정"을 세 줄로 나눠 적었다. 원안의 여섯 수단(내장 치트 / 시나리오 설정 / 데이터 표 / 실행 중 훅 / 세이브 편집 / Workshop)은 그대로다.

## 분류표

한 행이 "항목 하나를 수단 하나로 바꾸는 방법"이다. 같은 항목이 수단마다 행을 가진다. 내장 치트의 "검증"은 [07](07-cheats.md)의 표기를 그대로 옮겼다. "반응 없음"은 본 화면에서 변화가 없었다는 뜻이다.

## 만들 것

### ToyBox — 게임 안 모드 설정 창 (1단계를 만들었다)

2026-10-06 에 사용자가 요구를 둘 정했다: 모드의 모든 기능은 **게임 안의 설정 창**에서 설정하고, 설정은 **플레이어가 플레이 중인 국가에만** 적용한다.
아래의 시나리오 모드는 지역 번호에 고정이고 새 게임을 시작할 때만 적용되어 이 요구를 채우지 못한다. 그래서 이 문서가 처음에
"만들지 않는다"고 했던 실행 중 수단(훅 DLL 확장)으로 방향을 바꿨다 — [10 ToyBox](10-toybox.md).

1단계는 창과, 게임이 플레이어에게만 적용하는 내장 치트 16개다. 내장 치트가 없는 GDP 와 장비 수치는 뒷단계다(10 의 "다음 단계").
아래의 시나리오 덮어쓰기는 그때의 후보로 남긴다.

### 내 플레이용 시나리오 모드

게임의 시나리오 파일 끝에 덮어쓰기 블록을 덧붙인 시나리오. **GDP 와 부대 스탯을 바꾸는 유일하게 깨끗한 길이고, 치트가 사라질 때의 대체 수단이기도 하다.**

- **무엇을 바꾸나**: 내가 고른 지역의 `gdpc` · `treasury`(`&&CVP <지역>`), 내가 고른 장비의 비용 · 건조 일수 · 공격 · 방어(`&&UNITS` 행 + `&&REGIONUNITDESIGNS <지역>`), 필요하면 `&&GMC` 의 기본값.
- **만드는 방식**: 시나리오 파일은 게임 파일이라 저장소에 넣지 않는다. 저장소에는 덧붙일 블록과 설정만 두고(`mods/<이름>/`), 빌드할 때 설치된 시나리오 파일에 붙여 `build/<이름>/` 에 만든다 — `srkit probe` 가 이미 하는 일이다. 게임이 업데이트되어 시나리오 파일이 바뀌어도 다시 빌드하면 된다.
- **캐시**: 다시 만들지 않는다 [확인]. 캐시 파일을 건드리지 않으므로 빼면 원래대로다.
- **먼저 확인할 것**: ① 기존 시나리오를 덮어쓰지 않고 새 이름의 시나리오로 둘 수 있는가(MAPS 유형 — [02](02-modding-system.md)). 새 이름이면 원본 샌드박스가 그대로 남는다 → **된다** [확인: 게임]. `Sandbox\World2030X.scenario` 와 같은 이름의 폴더(지역 설정 csv, `World2030XStart.csv`)를 두면 샌드박스 목록에 뜨고 덮어쓰기가 반영된다. 표시 이름은 `LocalText-START.csv` 의 `&&FILETEXT` 에서 온다 ② 공격 · 방어 · 일수 열도 비용처럼 반영되는가 ③ `&&UNITS` 로 고친 장비를 다른 지역이 잃는가 ④ `treasury` 를 아주 크게 줬을 때의 부작용.
- **시험**: `srkit probe` → `srkit deploy` → 화면 밖 게임에서 확인 → `srkit undeploy`. 이번 검증에서 쓴 절차 그대로다.

### 장비 덮어쓰기 행을 만드는 도구

`&&UNITS` 는 155열짜리 행을 통째로 적어야 한다. 손으로 쓰면 틀리기 쉬우므로, 설치본의 `DEFAULT.UNIT` 에서 고른 장비의 행을 읽어 지정한 열만 바꾼 행을 내는 명령을 `srkit` 에 더한다. 열 이름은 [06](06-data-reference.md)에 있다.

## 게임 업데이트 대비

이 게임의 데이터 파일은 2025년 12월에 만들어진 것이고(파일 머리의 Asset Manager 시각 **[확인]**). 사용자에 따르면 그 뒤 열 달쯤 업데이트가 없었다(이 저장소에서 따로 확인하지는 않았다). 그래도 다른 게임들처럼 업데이트가 내장 치트나 그 입구를 없앨 수 있다. 아래는 그때를 위한 준비다.

### 무엇이 사라질 수 있나

| 원하는 것 | 치트 없는 대체 수단 | 검증 |

대체 수단은 모두 **새 게임을 시작할 때** 적용된다. 진행 중인 게임의 값을 바꾸는 것은 내장 치트뿐이고, 치트가 사라지면 남는 것은 게임 밖 프로그램(Workshop 의 트레이너, 세이브 편집기)이다 — 이 저장소에서는 써 보지 않았다.

**그래서 로드맵의 첫 단계를 "시나리오 덮어쓰기 모드"로 잡았다.** 치트에 기대지 않는 수단을 먼저 갖춰 두면 업데이트가 와도 쓸 것이 남는다. 표에서 [위키] · [추정]인 줄(`techlevel`, `stockadd`, 이벤트 10, `refpopulation`)은 그 모드를 만들면서 하나씩 게임에서 확인한다.

### 지금 판을 붙잡아 두는 방법

게임 파일은 사용자의 것이고 저장소에 넣지 않는다. 아래는 사용자가 고를 수 있는 일이며 이 저장소가 대신 하지 않는다.

- **Steam 의 자동 업데이트를 늦춘다**: 라이브러리 → 게임 속성 → 업데이트 → "이 게임을 실행할 때만 업데이트". 이 저장소의 검증은 Steam 을 거치지 않고 실행 파일을 바로 띄운다 [확인: `gamedrive.py start`]. 그렇게 띄울 때 Steam 이 업데이트를 먼저 받는지, Steam 이 꺼져 있어도 되는지는 확인하지 않았다.
- **게임 폴더를 저장소 밖에 통째로 복사해 둔다**(약 2 GB). 업데이트가 치트를 없애면 복사본으로 플레이한다. `srkit.toml` 의 `game_dir` 을 복사본으로 돌리면 도구도 그쪽을 본다.
- 업데이트가 이미 받아진 뒤에 옛 판을 되찾는 방법(Steam 의 옛 빌드 내려받기)은 이 게임에서 확인하지 않았다 [추정].

## 로드맵

각 단계는 따로 설계 → 계획 → 구현 주기를 돈다.

1. **ToyBox 1단계 (끝).** 게임 안 설정 창 + 플레이어 대상 내장 치트 — [10](10-toybox.md).
2. **ToyBox 2단계 (끝).** 게임 상태 읽기, 치트의 직접 실행, 나라를 골라 쓰는 치트 — [10](10-toybox.md), 게임의 안쪽은 [11](11-game-internals.md).
3. **ToyBox 3단계 (진행 중).** 모든 기능을 내장 치트에서 떼어 내고(사용자의 요구, 2026-10-09), 돈 · 물자 · 연구 · 부대를 세분화한다 —
   여덟 묶음([설계](superpowers/specs/2026-10-09-toybox-stage3-1-design.md)). 첫 묶음의 (가) 치트와 무관한 주소 찾기와 (나) 값 쓰기의 바탕 · 돈 탭이 끝났다(2026-10-09). 다음은 (다) 물자 탭 · 최소 유지 — [10](10-toybox.md).
4. **(3단계 뒤)** GDP 와 장비 수치처럼 내장 치트가 처음부터 없던 값.
5. **(업데이트가 오면)** `srkit cheats-check` → `srkit locate`(서명이 아직 맞는가, 치트 명령 처리 함수가 남아 있는가) → 깨진 서명은 `srkit sig-mine` 으로 다시 뽑고([11](11-game-internals.md))
   → 달라진 치트를 게임에서 다시 넣어 보고 [07](07-cheats.md) 갱신 → `srkit inventory` 로 형식 변화 확인 → ToyBox 가 뜨는지 확인.

## 미해결 문제

- **"반응 없음"으로 남은 치트 가운데 관찰이 약했던 것**: `revolt` `reviveall` `dipaccept` `moreoffers` `unitdesign` `selloffunits` `nomove` `007` `maxsat` `satellite` `speedlock` `blueskies` `airequest` `noaiinit` `killeveryone` `done` `discovered` `known`(뒤의 셋은 인자 없이 넣었다). 볼 화면을 찾지 못했거나 조건이 나빴다. 쓸 일이 생기면 다시 본다.
- **치트가 Steam 업적을 막는가.** 화면에 표시는 없었다. 실행 파일에서는 치트 허용 비트가 서 있으면 업적을 주는 호출 19곳을 건너뛴다 [확인: 정적 — [11](11-game-internals.md)]. 실제로 막히는지는 여전히 해 보지 않았다.
- **`onedaybuild` · `allunit` · `breakground` 가 AI 에게도 적용되는가.** 위키는 그렇다고 하나 AI 쪽은 보지 않았다.
- **`trumpme` 의 방향.** 첫 입력은 빼기였다. 국고의 부호를 따르는지 번갈아 뒤집는지는 가리지 못했다.
- **실행 파일에만 있는 시나리오 설정 키**(`magicresupply`, `nounits`, `ignorecache` 등 — [06](06-data-reference.md))의 실제 동작. 일부는 로비 옵션으로 드러나 있다(전장의 안개, 유닛 없이 시작).
- **Workshop 14개 항목의 필요 DLC.** 페이지를 열지 못했다([08](08-workshop-survey.md)).
- **`INI\AllLoad.ini` 가 매번 읽는 파일**(AI 매개변수, 지형)을 고치면 진행 중인 게임에도 반영되는가. 시험하지 않았다.

## 검증 기록

모두 2026-10-06, build `21347933`, 화면 밖에서 띄운 게임(`scripts/gamedrive.py`)의 2030 - 세계 · 독일. 근거 화면과 기록은 로컬 산출물(`build/verify/`)에 있고 저장소에는 넣지 않는다.

- **V1 내장 치트.** 입력 경로: 채팅 창과 게임 메뉴로는 치트 입력란이 열리지 않았고, `gamedrive.py` 에 조합키를 더해 `Ctrl+Shift+S` 로 게임 설정 창을 열었다. 89개를 일곱 묶음으로 넣었다: 효과 45, 반응 없음 44. `resettutorial` 은 넣지 않았다. 결과는 [07](07-cheats.md).
- **V2 장비 데이터와 캐시.** `DEFAULT.UNIT` 에서 Leopard 2A7+ 의 비용 6 → 66. 캐시 재생성 없이는 건설 비용 $579 M 그대로, 로비의 "모드용 캐시 재생성" 뒤에는 $6,373 M. 게임이 `Cache\W2030.SAV` 를 고쳐 썼다(11,896,414 → 11,888,549 바이트).
- **V3 시나리오 설정.** `&&GMC` 의 `initialfunds` 2 → 3. 재생성 없이 로비 초기 자금 "기본" → "많음", 시작 국고 $14.43 B → $57.72 B.

- **V5 시나리오 파일 끝 덮어쓰기**(조사 중에 위키에서 찾아 더한 실험). 재생성 없이: `&&CVP 1499` 의 `gdpc 99999` → $99,999, `treasury 100000000000` → 국고 $100.00 B(`50000` 은 $50.00 K). `&&UNITS` 행만 덧붙이면 그 장비가 설계 목록에서 사라졌고, `&&REGIONUNITDESIGNS 1499` 를 함께 붙이자 목록에 남으면서 건설 비용이 $6,373 M 이 됐다.

**게임 폴더는 실험마다 원래대로 되돌렸다.** 시험 모드는 `srkit undeploy` 로 지웠고, 실험 전에 적어 둔 해시와 대조했다. 캐시를 다시 만든 두 번(V2, V4)은 게임이 고쳐 쓴 `Cache\W2030.SAV` 를 미리 떠 둔 원본으로 되돌렸다. 마지막 확인: 시나리오 · 지역 · 장비 파일과 캐시 일곱 개의 해시가 모두 실험 전과 같고, 한글화 모드의 설치 상태도 그대로다.
