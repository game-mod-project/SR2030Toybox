# 10. ToyBox — 게임 안 모드 설정 창

조사 기준: Steam appid `2093410`, build `21347933`(게임 12.1.1360), Windows 11(`dxgi.dll` 10.0.26100), 2026-10-06.

표기: **[확인]** 게임 안에서 직접 봤다 · **[추정]** 정황으로 판단했고 게임에서 보지 않았다.

## 무엇인가

게임 화면 위에 뜨는 치트 창이다. 창의 단추를 누르면 게임의 내장 치트([07](07-cheats.md))를 대신 넣어 준다. 요구는 둘이었다(2026-10-06, 사용자):

1. 모드의 모든 기능은 **게임 안의 설정 창**에서 설정한다. 설정 파일을 고쳐 다시 빌드하지 않는다.
2. 설정한 내용은 **플레이어가 지금 플레이 중인 국가에만** 적용된다.

지금은 1단계다: 창과, 게임이 스스로 플레이어에게만 적용하는 내장 치트 16개. 싱글플레이 전용이고 Workshop 으로는 배포할 수 없다
(DLL 은 게임의 파일 로더를 거치지 않는다 — [02](02-modding-system.md)).

## 설치와 제거

```
uv run srkit hook-build              # 불러오기가 든 한글화 훅 DLL
uv run srkit build                   # 한글화 모드에 새 훅 DLL 을 넣는다
uv run srkit deploy korean --apply   # 갱신: WTSAPI32.dll 한 개
uv run srkit toybox-build            # build/toybox/srtoybox.dll
uv run srkit deploy toybox --apply   # 추가: srtoybox.dll 한 개
uv run srkit undeploy toybox --apply # ToyBox 만 뺀다
```

- **한글화 모드가 설치되어 있어야 동작한다.** 게임 폴더의 `WTSAPI32.dll`(한글화의 훅)이 옆에 있는 `srtoybox.dll` 을 불러온다. 게임 언어가
  한국어가 아니어도 불러오기는 된다 [추정: 불러오기는 언어를 보지 않는다].
- ToyBox 를 빼도 `WTSAPI32.dll` 은 한글화 모드의 파일로 남는다. `srtoybox.dll` 이 없으면 아무 일도 하지 않는다 **[확인: G8]**.
- 게임이 실행 중이면 `deploy` · `undeploy` 는 거부된다.

## 쓰는 법

- **`Ctrl+Shift+T`** 로 창을 열고 닫는다 **[확인]**. 게임이 쓰지 않는 조합이다(`INI\hotkeys.csv`).
- 탭: 돈 / 물자 / 연구 / 인구·여론 / 부대 / 화면·진행 / 설정. 단추를 누르면 그 기능이 실행된다.
- 숫자가 필요한 기능은 왼쪽 입력란에 값을 넣고 단추를 누른다. 입력란을 누르면 전체가 선택되므로 바로 치면 된다. 넣은 값은 저장된다 **[확인: G3 · G7]**.
- "즉시 승리"는 한 번 누르면 "한 번 더 누르면 실행합니다"로 바뀌고, 한 번 더 눌러야 실행된다 [추정: 게임에서 눌러 보지 않았다].
- **단추를 누르면 게임의 설정 창이 잠깐 열렸다 닫힌다** **[확인]**. ToyBox 가 그 창에 치트를 넣는 것이다. 한 명령에 4초쯤 걸리고,
  그동안 누른 것은 줄을 선다(최대 8개).
- **넣는 동안 키보드로 친 글쇠는 게임에 가지 않는다** — 치트를 받아 적는 줄에 섞이지 않게 ToyBox 가 삼킨다 **[확인: R6]**.
  창을 여닫는 단축키는 그동안에도 듣는다 [확인: 자동 테스트]. 마우스는 막지 않는다("한계").
- 단축키는 "설정" 탭의 "단축키 바꾸기"를 누르고 새 조합을 누르면 바뀐다 **[확인: G7]**. `ESC` 는 취소다 **[확인: R5]**.
- 창이 열려 있는 동안 창 위의 마우스는 게임으로 가지 않는다 **[확인: G5 · G6]**. 입력란에 초점이 있는 동안의 글쇠도 가지 않는다
  **[확인: R3 · R4 — `S`(게임에서는 보급 지도) 한 글쇠로 봤다]**.

  `becomeregion` — 다음 단계.
- GDP 와 장비 수치 — 내장 치트가 없다. 다음 단계.

## 한계

- **단추마다 게임의 설정 창이 잠깐 보인다.** 게임의 명령 처리 함수를 직접 부르면 없어지지만 실행 파일을 분석해야 한다(다음 단계).
- **게임이 진행 중인지 ToyBox 는 모른다.** 창의 아래쪽에 안내가 늘 떠 있다. 진행 중이 아닐 때 눌러 본 화면은 둘이다 **[확인]**:
  - 메인 메뉴: 눈에 보이는 변화가 없다(글자와 `ESC` 가 무시된다). Steam 으로 띄운 게임에서도 같다.
  - 로비(샌드박스 선택 화면): `ESC` 가 "뒤로"로 먹혀 메인 메뉴로 돌아간다.
  - **그 밖의 화면에서는 눌러 보지 않았다**(저장 · 불러오기 창, 옵션, 캠페인 선택, 게임 안의 메뉴 등). 글자와 `Enter` · `ESC` 가
    그 화면의 입력으로 들어가므로, 이름을 적는 칸이 열려 있으면(예: 저장 창) 그 칸에 글자가 들어가고 `Enter` 로 확정될 수 있다 [추정].
    게임을 진행하는 중에만 누른다.
- **넣는 4초 동안 마우스는 막지 않는다.** 그 사이에 게임의 다른 곳을 누르면 게임의 설정 창이 초점을 잃어 글자가 엉뚱한 곳에 들어갈 수 있다 [추정].
- **연구 화면의 "보유 기술" 목록이 열려 있으면** 글자가 그 검색란으로 들어간다(07 의 "알아 둘 것"). 다른 패널을 연 채로 누른다.
- **게임이 `Ctrl+Shift+S`(게임 설정 창)나 치트를 없애면 동작하지 않는다.** `uv run srkit cheats-check` 가 그 변화를 알린다([09](09-cheat-mod-plan.md)).
- **치트를 쓰면 Steam 업적이 막히는지 모른다**(07 의 미해결 문제 그대로).
- **Steam 오버레이(`Shift+Tab`)가 ToyBox 와 함께 열리는지는 보지 못했다.** 검증 도구가 보낸 `Shift+Tab` 에는 화면이 달라지지 않았다
  (오버레이는 창 메시지가 아니라 실제 키보드를 본다 [추정]). Steam 으로 띄운 게임이 죽지 않고, ToyBox 창이 뜨고, 스스로 끝나는 것까지
  확인했다(아래 "확인한 것").
- **게임이 앞 창일 때(= 실제로 게임을 하는 중에) 단추를 눌러 보지 못했다.** 검증에서는 게임 창이 늘 화면 밖 · 뒤에 있었다. 그때 ToyBox 는
  넣은 뒤 `Ctrl` · `Shift` 를 넣기 전 상태로 되돌린다 **[확인]**. 앞 창일 때는 실제 키보드의 상태를 읽어 맞추는데(`runner_win.cpp`),
  이 갈래는 한 번도 돌지 않았다 [추정]. 검증 도구로 게임을 앞 창에 올리려 했으나 Windows 가 두 방법을 모두 거부했다(2026-10-06).
  치트를 넣은 뒤 `Ctrl` 이나 `Shift` 가 눌린 것처럼 굴면 그 글쇠를 한 번 눌렀다 떼면 풀린다 [추정].
- **Steam 오버레이와 함께 돌 때 다른 오버레이 · 녹화 프로그램이 화면을 못 받을 수 있다** [추정: 해 보지 않았다]. 그때 ToyBox 는
  진짜 `Present` 의 머리를 건너뛰는 길로 간다("구조"). 같은 머리에 점프를 심어 화면을 받는 프로그램(OBS 의 게임 캡처, Discord 오버레이,
  RivaTuner 류)이 Steam 오버레이보다 먼저 걸려 있었다면 그 훅도 함께 건너뛴다. 그런 프로그램에서 게임이 안 보이면 ToyBox 를 끄고
  (`SRTOYBOX=0`) 견주어 본다.
- **게임 창의 크기와 그리는 크기가 다르면** 설정 창이 그 비율로 늘어나(줄어) 보인다. 마우스는 그 비율로 맞춘다
  **[확인: 자동 테스트 — 그리는 크기가 창의 절반일 때]**. 게임에서 그런 상태를 만들어 보지는 않았다(본 것은 둘이 같은 1024x768 창과
  1920x1080 화면 크기 창이다).
- **ToyBox 는 다음 가운데 하나면 끼어들지 않는다**(게임은 그대로, 로그에 까닭) **[확인: 자동 테스트]**: `dxgi.dll` 의 함수 머리가
  ToyBox 가 모르는 명령으로 시작한다(다른 Windows 판) / 다른 훅이 그 머리를 14바이트보다 길게 고쳐 놓았다 / 올라와 있는 `dxgi.dll` 이
  디스크의 파일과 다른 판이다(게임이 떠 있는 동안 Windows 가 파일을 바꿨다).

## 구조

```
게임 프로세스
  WTSAPI32.dll (srhook, 한글화 훅)  ──(옆에 있으면 불러온다)──▶  srtoybox.dll
                                                                 ├─ 화면 끼어들기   swap chain 의 Present · Present1 · ResizeBuffers
                                                                 ├─ 입력 끼어들기   게임 창의 창 프로시저
                                                                 ├─ 창             Dear ImGui (Win32 + DirectX 11 백엔드)
                                                                 ├─ 기능 표        이름 · 탭 · 명령 · 값의 범위
                                                                 ├─ 명령 실행기    게임의 설정 창에 치트를 대신 넣는다
                                                                 └─ 설정 · 로그    %APPDATA%\SR2030ToyBox\
```

| 파일 (`native/srtoybox/`) | 하는 일 |
|---|---|
| `features` | 기능 표 16줄 |
| `command` | 기능 → 넣을 글, 그 글을 넣는 동작의 순서(순수 함수) |
| `runner` · `runner_win` | 대기열과 간격 지키기 · 게임 창에 실제로 보내기 |
| `settings` · `log` | `toybox.ini` · `toybox.log` |
| `overlay` · `prologue` | 화면 끼어들기와 그리기 · 다른 훅을 건너뛰는 진입로 |
| `input` | 창 프로시저 감싸기, 타이머, 단축키, 넣는 동안 사용자의 글쇠 거르기 |
| `ui` | 창의 내용 |
| `exports` | 테스트와 훅이 쓰는 C 인터페이스 |

- **실행 파일의 주소를 쓰지 않는다.** 임시 swap chain 에서 가상 함수 표의 주소를 얻어 `Present` 의 칸을 바꾼다. 게임이 그리는 창을
  주 창으로 삼는다. 게임이 업데이트되어도 이 부분은 다시 찾을 것이 없다.
- **명령 실행기**는 `scripts/gamedrive.py` 가 밖에서 하는 일을 게임 안에서 한다: 키 상태표에 `Ctrl` · `Shift` 를 눌린 것으로 적고
  `Ctrl+Shift+S` 를 보내 설정 창을 연 뒤, `cheat allowcheats`(두 번 넣어도 치트는 켜진 채다 **[확인]**)와 명령을 글자로 넣고 `ESC` 로 닫는다.
  창 스레드의 10 ms 타이머에서 한 걸음씩 보낸다.
- **Steam 오버레이와 함께 돌기.** Steam 오버레이는 진짜 `Present` 의 머리에 점프를 심어 두고, 표에서 본 ToyBox 의 함수를 "원래 함수"로
  부른다. ToyBox 가 진짜 함수를 그대로 부르면 그 점프를 타고 오버레이로 되돌아가 서로 맴돈다 — 처음 두 번은 그렇게 게임이 죽었다
  **[확인: 충돌 덤프]**. 그래서 끼어들 때 `dxgi.dll` 파일에서 함수의 원래 첫 명령들을 읽어, 그것을 실행하고 함수의 그 다음 자리로 뛰는
  "깨끗한 진입로"를 만들어 둔다. 되불렸거나, 표의 칸이 바뀌었거나, ToyBox 의 함수 머리에 점프가 심겼으면 그 길로 간다.
  진입로는 "함수의 첫 14바이트 뒤는 파일과 같다"는 가정 위에 있다. 그래서 끼어들 때 그 뒤의 바이트와 DLL 의 머리말(만든 시각 · 크기 ·
  체크섬)을 메모리의 것과 견주고, 다르면 끼어들지 않는다. `Present` 와 `ResizeBuffers` 는 둘 다 될 때만 함께 끼어든다 — 그리기만 하고
  크기 바꾸기를 놓치면 뒷면을 쥔 채 놓지 못한다.
- **실행기의 글쇠와 사용자의 글쇠를 가르는 법.** 실행기가 보내는 메시지에는 스캔 코드가 없고(`lParam` 의 16 ~ 23번 비트가 0) 실제
  키보드의 것에는 있다. 넣는 동안 스캔 코드가 있는 누름과 글자는 게임에 넘기지 않는다(뗌과 `Alt` 조합은 넘긴다).
  `scripts/gamedrive.py` 가 보내는 글쇠에도 스캔 코드가 없어, 검증 도구로는 이 거르기를 지나친다.
- 외부 소스는 Dear ImGui 하나다(`native/third_party/imgui/README.md` 에 버전과 출처. MIT).

그 밖에 **[확인]**:

- 치트를 넣은 뒤 맨 `S` 를 보내면 설정 창이 아니라 보급 지도가 켜진다 — 수정키가 눌린 채 남지 않는다.
- 창을 연 채 게임 창의 크기를 바꿔도(1024x768 → 1280x800 → 되돌림) 게임이 죽지 않고 창이 계속 그려진다.
- **Steam 으로 띄운 게임**(화면 크기 창 1920x1080. 검증 도구가 창을 화면 밖 · 뒤에 둔다): 메인 메뉴에서 창이 한글로 뜬다(`steam-open`,
  고친 뒤 `steam2-open`). 로그에 `화면에 끼어들었습니다 (다른 훅이 먼저 있습니다)` → `다른 훅과 함께 돕니다 (우리 함수의 머리에 점프가 심겼다)`.
  - 메인 메뉴에서 "국고 +$10 B"를 누르면 넣기가 끝까지 가고(`마지막으로 넣은 것: cheat georgew`) 화면은 그대로다. 그 뒤 맨 `T` 를 보내도
    창이 닫히지 않는다 — 수정키가 눌린 채 남지 않는다(`steam2-injected` `steam2-bareT`).
  - 창을 닫고 게임 창에 `WM_CLOSE`(창의 닫기 단추 · `Alt+F4` 와 같은 길)를 보내면 1.1초 뒤 게임이 스스로 끝난다. 이벤트 로그에 충돌 기록이 없다.
  - 처음 확인(`steam-open`) 때는 검증 도구가 게임을 강제 종료(`taskkill`)했다. 그때 본 것은 "죽지 않았다"까지다.
  - 보지 못한 것: 게임을 진행하는 중의 치트(Steam 으로 띄운 게임에는 검증 도구의 가상 마우스가 없어 게임의 메뉴를 누를 수 없다 —
    화면 밖 게임과 같은 길이다 [추정]), 게임이 앞 창일 때의 넣기, `Shift+Tab` 오버레이. "한계"에 적었다.

자동 테스트(`tests/test_toybox.py`)는 기능 표와 07 의 대조, 명령과 동작의 순서, 간격, 대기열, 설정을 본다. 화면과 입력은
`tests/toybox_overlay_probe.py` 가 게임 없이 실제 Direct3D 장치와 가짜 "게임 창"으로 밟는다:

- 다른 훅을 흉내 낸 `Present` · `Present1` · `ResizeBuffers` 호출 — 표의 칸을 바꾸는 훅, 함수 머리에 점프를 심는 훅,
  Steam 오버레이가 실제로 만든 배치(진짜 함수와 ToyBox 함수 양쪽 머리에 점프).
- 끼어들면 안 되는 경우 셋("한계"의 마지막 항목), 실제로 그리는지와 크기 바꾸기 때 뒷면을 놓는지.
- 입력 — 단축키, 창 위와 밖의 누름, 넣는 동안의 실제 글쇠와 단축키, 그리는 크기가 창과 다를 때의 마우스.

**화면 밖 검증만으로는 Steam 오버레이와의 문제를 볼 수 없다.** 화면 끼어들기(`overlay.cpp`)를 고치면 `gamedrive.py steam` 으로 띄워 확인한다.

## 문제가 생기면

`%APPDATA%\SR2030ToyBox\toybox.log` 를 본다(환경 변수 `SRTOYBOX_HOME` 이 있으면 그 폴더).

| 로그의 줄 | 뜻 |
|---|---|
| `시작` | 훅이 ToyBox 를 불러왔다. 이 줄이 없으면 `srtoybox.dll` 이 게임 폴더에 없거나 한글화 훅이 옛 것이다 |
| `화면에 끼어들었습니다` | 준비됐다. `(다른 훅이 먼저 있습니다)`가 붙으면 Steam 오버레이 같은 것이 함께 돈다 |
| `창 준비됨 (가로x세로)` | 게임의 첫 화면에서 창을 그릴 준비를 마쳤다. 이 줄 뒤로 단축키가 듣는다 |
| `다른 훅과 함께 돕니다 (…)` | 다른 훅을 만나 깨끗한 진입로로 가고 있다(정상) |
| `화면에 끼어들지 못했습니다 (…)` | ToyBox 는 동작하지 않는다. 게임은 그대로다. 괄호 안이 까닭이다 — `원래 함수의 머리를 옮길 수 없습니다`(ToyBox 가 모르는 명령), `다른 훅이 원래 함수의 머리를 길게 고쳐 놓았습니다`, `올라와 있는 DLL 이 디스크의 파일과 다릅니다`(Windows 를 다시 시작하면 풀린다 [추정]), 숫자(Direct3D 장치를 만들지 못했다) |
| `Present1 에는 끼어들지 못했습니다 (…)` | 게임이 그 함수로 화면을 내보낼 때만 창이 보이지 않는다. 나머지는 동작한다 |
| `DirectX 11 장치가 아닙니다` · `ImGui 초기화에 실패했습니다` | 위와 같다 |
| `맑은 고딕(malgun.ttf)이 없습니다` | 창은 뜨지만 한글이 깨진다 |

- 끄려면: `uv run srkit undeploy toybox --apply`. 파일을 둔 채 끄려면 환경 변수 `SRTOYBOX=0` 을 준 채로 게임을 띄운다.
- 설정을 처음으로 돌리려면 `toybox.ini` 를 지운다(깨진 파일과 범위 밖의 값은 저절로 기본값이 된다).
- 게임이 죽으면 `%LOCALAPPDATA%\CrashDumps\SupremeRuler2030.exe.<번호>.dmp` 와 빌드할 때 생기는 `build/toybox-obj/srtoybox.map`
  으로 어느 함수인지 찾을 수 있다.
